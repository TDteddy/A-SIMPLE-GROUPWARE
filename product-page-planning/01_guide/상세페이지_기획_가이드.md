# Part A. 대시보드 기획안 가이드라인 (기준 문서 요약)

> 아래는 대시보드 원문을 구조만 정리한 요약입니다. 해석이 갈리면 원문을 우선합니다.

## A0. 공통 작성법 — 구매 이유부터 원고까지 (7단계)
> 주용도 안에서 고를 이유를 정하고, 짧게 어필한 뒤, 뒤의 영역마다 새로운 판단 정보와 근거를 더합니다. 모든 유형에 공통입니다.

| 단계 | 정할 것 | 작성할 때 확인 |
|---|---|---|
| 1 명칭과 첫 화면 결정 | 소싱명 / 일반 카테고리명 / 판매용 고유명 / 승인 상태 / 첫 화면 표현 방식 | 이미지 중심·최소 텍스트. 키카피는 확정 자사 고유명만. 판매명 미정이면 무카피 또는 확인된 매력 하나. 가칭·SKU 코드 금지 |
| 2 구매 이유 정리 | 주용도 / 고객이 하려는 일 / 구매 계기 / 기대하는 변화 / 이 방식을 고를 이유 / 구조·구성 / 근거 / 맞지 않는 조건 | 광고 말투 전의 내부 기획. 설치·일상 사용·관리·이동·보관을 실제 행동대로 구분. **반복 후기가 적거나 선별됐으면 타깃은 가설로 기록** |
| 3 위험과 단순 불편 분리 | 실제 위험 상황 / 발생 경로 / 가능한 피해 / 관련 자료 / 준비 필요성 / 제품이 맡는 범위 / SP로 옮길 편의 | 안전 주의문만으로 위험소구를 대신하지 않음. 일반 위험의 근거를 자사 제품의 예방 효능으로 바꾸지 않음. 위험이 없으면 영역 자리는 두고 미적용 사유 기록 |
| 4 주장과 근거 연결 | 소비자에게 말할 이점 / 근거의 실제 내용 / 출처와 옵션 / 뒷받침하는 범위 / 부족한 자료 / 현재 쓸 문구 | 확인된 구조에서 바로 설명할 수 있는 동작을 모두 실험 대기로 돌리지 않음. 유지 시간·하중·효과·우열은 자료에 연결 |
| 5 13영역 새 정보 배정 | 유형별 순서 / 고객 질문 / 앞에서 없던 정보 / 원고의 역할 / 증거와 미디어 / 보류 부분의 확보 요청 | 역할·근거·경계를 나누되 원고 형식을 한 문장 공식으로 통일하지 않음 |
| 6 메인 후보와 원고 작성 | 무카피·확정 고유명형·이점형 등 **다른 관점의 후보** / 근거·대표 장면 / **채택 이유** / 필요한 텍스트만 | 후보는 내부에서 검토하고 화면에 모두 노출하지 않음 |
| 7 제작과 게시 준비 | 재사용 자산 / 새 촬영·실험·편집 요청 / 확보할 원본 / 결과에 따라 바꿀 문구 / 실제 결과물 검토 상태 | 기획 완료 · 촬영/생성 완료 · 검토 완료 · 게시 완료를 나눔 |

### A0-1. 근거가 설명할 수 있는 범위 (4유형)
| 근거 종류 | 쓸 수 있는 내용 | 추가 확인 |
|---|---|---|
| 확인된 구조와 동작 | 그 동작이 가능하다는 사용 방식 | 하중·반복 수명·유지 시간은 별도 근거 |
| 실제 사용자 경험(원문) | 그 사용자의 경험을 원문 인용, 인용 범위 표시 | 한 사람의 경험을 모든 조건의 성능·대표 동기·만족률로 확대하지 않음 |
| 아직 하지 않은 실험 | 내부 제작 요청과 판정 기준 | 원본·관찰 기록·결과 확인 전까지 결과 카피와 검증 완료 표시 보류 |
| 일반 위험 자료 | 위험 경로와 준비 필요성 | 특정 제품의 성능·예방 효능을 입증하지 않음 |

### A0-2. 선택에 도움이 되는 비교표 (양식)
- 질문: 고객은 지금 **어떤 두 선택** 사이에서 고민하는가?
- 열: `선택에 영향을 주는 항목` / `방식·옵션 A의 사실` / `방식·옵션 B의 사실` / `차이가 의미하는 선택 조건`
- 공통 우열 판정 대신 "어떤 요구에는 우리 방식, 어떤 조건에는 다른 방식"으로 마무리합니다.
- 표를 읽어도 선택이 달라지지 않으면 기능 유무 나열을 줄이고 실제 과업·조건으로 축을 다시 잡습니다.

## A1. 기본 방향
- 고객의 실제 불편과 필요를 짚고, 제품이 제안하는 변화와 그 이유를 납득시킵니다.
- 모든 영역에서 문제를 반복하거나 모든 제목을 '불편하지 않으세요? / 이제 해결하세요'로 만들지 않습니다. 영역마다 역할이 다릅니다.
- **유지할 흐름**: 정품·판매처 신뢰 → 제품의 첫인상 → 나와 관련된 사용 상황 → 실제 위험과 준비 필요성 → 실제 평가와 공신력 → 설계·기술의 이유 → 개별 장점 → 비교와 선택 → 제품정보 → 상품정보고시 → Q&A·주의사항 → 브랜드 소개

**작성 전 내부에서 정할 것** (키비주얼에 다 넣는 항목이 아닙니다)
- **고객 상황**: 누가 무엇을 하려는가
- **명칭**: 소싱명, 카테고리명, 확정 자사 고유 상품명을 구분합니다. 이름이 미정이면 키카피로 쓸 이름을 만들지 않습니다
- **위험과 불편**: 실제 위험(04), 편의 개선(07 SP), 규격·옵션 고민(08·09·11)으로 나눠 배정합니다. 사실과 가설을 구분합니다
- **제품의 제안**: 그 상황을 어떻게 바꾸는가
- **근거**: 구조, 사양, 실제 사용, 시험, 후기
- **선택 이유와 조건**: 어떤 요구에 맞고 어떤 조건이 필요한가

## A3. 영역별 핵심 규칙 (원문 발췌 요약)
- **02 키비주얼**
  - 이미지 중심, 최소 텍스트로 구성하며 정해진 텍스트 조합은 없습니다.
  - 표현 유형은 고유 상품명형, 무카피 화보형, 대표 이점형, 대표 기능형, 콘셉트·감성형, 기능 요약형(꼭 필요할 때만) 중에서 고릅니다.
  - '맥세이프 차량용 거치대'는 N001의 소싱명입니다. 키카피로 쓰지 않고, 일반명 앞에 NORVEC만 붙여 고유명처럼 쓰지도 않습니다.
  - 판매명이 미정이면 무카피 화보형이나 확인된 매력 하나를 담은 짧은 카피를 씁니다.
  - 오해를 막는 핵심 조건(예: 비충전)은 가까이에 둡니다.
- **03 타겟·사용 상황**
  - 직업·연령보다 행동·공간·상황을 씁니다.
  - 1인칭 바람 문장에 작성자·별점·구매 인증을 붙이지 않습니다.
  - 운전 중 조작을 권하지 않습니다.
- **04 위험소구**
  - 근거 자료는 공공 안전자료·연구를 우선합니다. 부정 리뷰는 탐색의 출발점일 뿐 인과나 발생률의 증거가 아닙니다.
  - 위험 설명 뒤에 제품을 놓았을 때 '이 제품이면 사고를 막는다'는 암시가 생기지 않는지 연속해서 읽어 확인합니다.
  - 위험 장면은 정차 차량에서 연출하거나 도식으로 만듭니다.
  - 근거가 부족하면 기획 자리는 유지하고 소비자 원고는 보류합니다.
  - 피할 것: 근거 없는 사고 확률·반응시간·자력·고정 보장, 가격 상승·품절 공포
- **05 공신력·리뷰**
  - 판매자 제목, 고객 원문, 집계 수치를 분리합니다.
  - 요약을 따옴표에 넣지 않고, 외부 후기를 자사 후기로 오인시키지 않습니다.
  - 원문이 없으면 레이아웃과 확보 요청만 남깁니다.
- **06 연구개발·설계**
  - 보유한 자료에 맞는 유형(구조, 설계 이유, 시험)을 고릅니다.
  - 기성 상품에 자체 개발 이력을 만들지 않습니다. (2026-11-10 광고주 결정: '이력'은 구체 사실에 한정. 개발 어휘 자체는 D10-3에 따라 허용)
  - 04 뒤에 구조를 놓아 위험 해소가 입증된 것처럼 보이게 하지 않습니다.
- **07 SP**
  - 서로 다른 장점 1~4개를 씁니다. 탈부착, 각도 조절, 접이는 각각 출발 전 거치 준비, 화면 배치, 미사용 공간이라는 다른 이점입니다.
  - 동작명만 써 놓지 않고, 주행 중 조작을 편리함으로 홍보하지 않습니다.
  - 없는 기능을 성능 우위로 추론하지 않습니다(예: 비충전이니 저발열).
  - 요약판과 상세 SP를 구분합니다.
- **08 비교**
  - 비교 대상을 명확히 하고 같은 단위·조건으로 비교합니다. 모르는 값을 불리하게 채우지 않습니다.
  - 자사 선택 이유로 마무리하되, 제한과 다른 방식이 맞는 조건을 보존합니다.
  - 같은 구조의 경쟁품과 차이가 확인되지 않으면 USP라고 쓰지 않습니다.
- **09 제품정보**
  - 찾기 쉬운 제목을 씁니다.
  - 최초 설치, 평소 사용, 세척·관리, 이동·보관을 구분합니다.
  - 기본 제공품, 별매품, 연출 소품을 구분합니다.
- **10 고시**: 미확인 값은 내부 과제로 남깁니다. 임의 제조자·인증번호·보증 조건을 채우지 않습니다.
- **11 Q&A**
  - 결론과 조건을 먼저 답합니다. 증상 질문에는 원인 후보와 조치 순서를 답합니다.
  - 주의사항은 Q&A와 구분합니다.
  - 차량 조정은 '안전한 장소에 주차한 뒤'에 하도록 안내합니다. 신호 대기는 주차와 같지 않습니다.
- **12 브랜드**: 승인 공용 문구를 씁니다. 가상의 역사·조직·수상·보증을 만들지 않습니다.
- **13 내부 제작**

  - 시험에는 검증 질문, 표본, 조건, 절차, 관찰 기준, 원본, 결과별 문구 처리를 정합니다.
  - AI 연출은 증거가 아닙니다.

## B2. 오퍼 설계 (Part A 밖의 사업 결정 — 기획 전에 정리)
같은 본체를 파는 기성 상품은 판매처 간 차이가 **구성·가격·안내·지원**에 있습니다. 대시보드 상품마스터 `differentiation`에도 그렇게 적혀 있습니다.

- **지원 정책**(교환·보증)

- **가격**: 판매가 − 원가 − 수수료 − 물류 − 부가세로 손익을 추정하고, 대시보드 선정 기준(예상 마진 25% 이상, 예상 이익 3,000원 이상)과 대조합니다.
- 오퍼는 **사업 판단**이며 상세의 독립 영역이 아닙니다. 09(구성·옵션)와 08(옵션 선택 기준)에 녹입니다.

## B4. 증거 위계와 자체 시험

## NORVEC 보이스 프로필 (D3 결과, 샘플 10문장 기준 잠정)
- **한 문장**: 물건이 아니라 그 물건이 놓인 일상의 한 자리를 말하는, 짧고 단정한 목소리.
- **하세요**: 명사형 종결("휴대폰을 붙여 두는 일상의 자리") · 두 가지를 나란히("쓰임과 디자인을 함께") · 바람형 종결("~이기를") · 생활 동사(붙여 두다, 열다, 놓다, 비워 두다) · 한 줄 12자 안팎, 조사 최소
- **하지 마세요**: 감탄사·느낌표·"~해보세요!" · 최상급·형용사 겹치기 · 기능 나열·스펙 선두 · 기술 용어 선두 · 세 문장 넘는 설명
- **쓸 말**: 자리, 쓰임, 매일, 손이 가는, 두다, 비워 두다, 곁에, **쉬운·편한·간편한·가벼운(구체 동작과 함께)** / **피할 말**: 강력, 완벽, 혁신, 최고, 어디서나, 솔루션. (2026-11-10: '간편하게 남용 금지'를 완화 — 용이함 형용사는 동작·결과와 붙여 쓰면 KV에서도 권장)
- **리듬**: 짧은 명사구 → 조금 긴 서술 한 줄. 두 번째 줄이 첫 줄의 이유나 장면.

## D9. 키 카피 표현 기준 (2026-11-10 개정 3차, 광고주 결정 — 충돌 지침보다 우선)

**배경**: "받은 날 바로 설치"처럼 모든 거치대에 해당하는 당연한 장점을 키 카피로 그대로 쓰면 어필이 없다. 이 제품을 보는 소비자는 **이미 비슷한 거치대를 쓰고 있는 사람**(송풍구 집게형·송풍구 자석형·접착식·같은 구조의 다른 판매처 제품)을 포함하므로, 바꿀 이유가 보이게 쓴다.

**표현의 정도(과장·오인 가능성)는 지침으로 판정하지 않는다.** 작성·검수 에이전트는 "과장이 과하다", "오인될 수 있다", "보장처럼 읽힌다"를 판정 기준이나 감점 사유로 쓰지 않는다. 표현 수위의 판단은 **광고주(사람)의 몫**이며, 검수는 어필·즉시 이해·형식·자연스러움·글자 수·기존 방식과의 차이만 본다.

**키 카피에서 유지하는 것(법·안전 최소선)** — 2026-11-10: '맥세이프 호환' 표기·로고 금지 항목 삭제(광고주 결정)
- 주행 중 조작을 권하는 문장 금지(도로교통법).
- 느낌표 미사용(브랜드 보이스).

**기존 사용자 전환 어필**: 키 카피 또는 수식 줄에 **"지금 쓰는 방식"**(송풍구·집게·접착·컵홀더)을 한 번은 호명한다. 같은 구조의 타 판매처 제품을 쓰는 사람에게는 구성(링·패드 둘씩, 한국어 설명서)·조건 안내·지원 정책이 바꿀 이유가 된다(09·01).

**충돌 처리**: A3-07 "동작명만", A4-9, E1·E2(최상급·조건 없는 수치 점검), E4(주장↔조건 모순) 중 **키 카피에 관한 것은 이 절이 우선**한다. 보조문·본문·09·11의 사실 서술 원칙은 그대로 둔다.

### D10-1 용이함 형용사 (2026-11-10 추가, 광고주 지시)
- 그동안 KV에 '쉬운·편한·간편한' 같은 형용사를 쓰지 않은 근거는 ① NORVEC 보이스 프로필의 "간편하게(남용) 피함" ② copywriting 스킬의 "구체 > 막연"(형용사만으로는 경쟁사도 쓸 수 있는 문장) 두 가지였다. 둘 다 **단독 사용**을 경계한 것이지 금지가 아니었으므로, 아래로 정리한다.
- **용이함 형용사와 의성어는 KV에서 쓸 수 있는 선택지**이지, 모든 KEY에 넣으라는 뜻이 아니다. 07 KEY처럼 동작·부품으로 충분히 명료한 문장은 그대로 둔다. 쓸 때는 **구체 동작·결과와 붙여** 쓴다. `붙이기 쉬운`, `보기 편한`, `툭 붙이는 간편함`은 ○. `편리한 거치대`, `간편한 설치`처럼 동작 없이 형용사만 있는 것은 ✕(스왑 테스트 탈락).
- 레퍼런스 형식과 같다: `흔들리지 않는, 편안한 사운드` = [동작·상태 관형절] + [용이함 형용사 + 범주].

### D10-3 개발·설계 어휘 — 자체 개발 이력 없이도 쓴다 (2026-11-10 제정, 광고주 결정. A3-06 어휘 부분보다 우선)
- '만들었다·설계했다·생각했다·고민했다' 같은 **개발·설계의 말은 자체 개발 이력이 없어도 쓴다.** 기성 상품이라도 구조를 골라 파는 주체의 말로 자연스럽다.
- 지어내지 않는 것은 **구체 이력**뿐이다: 연구 기간, 연구소·개발팀, 특허·출원, 시험 항목·수치, 등록증을 성능 검증으로 넓히는 것(A3-06·대시보드 06 '피할 것' 그대로).
- 예(06 KEY): `어느 한 곳도 그냥 만들지 않았습니다.` ○ / `2년의 개발 끝에` ✕ / `자체 연구소 검증` ✕.

## D11. 카피 작성 선행 원칙과 키비주얼 초점 어휘 (2026-11-10 제정, 광고주 지시)

### D11-1 소비자의 상황·배경을 먼저 파악한다
- 카피를 쓰기 전에 **"이 제품을 보는 사람이 지금 무엇을 쓰고 있고, 무엇을 겪고 있는가"**를 자료(리뷰·조사)로 정리한다(기획안 §A-0 형식: 지금 방식 → 겪는 것 → 이 제품의 차이). 이 표가 없으면 키 카피를 쓰지 않는다.
- 이점은 **다수 집단이 겪는 것과의 차이**에서 고른다. 소수 집단(예: 접착식 사용자)에게만 닿는 차이를 KV에 두지 않는다. 모든 제품에 해당하는 당연한 장점(받은 날 설치 등)도 KV에 두지 않는다(D9).
- 작성·검수 에이전트 브리프에 §A-0 표를 반드시 첨부하고, 검수 기준 '차이' 항목은 **다수 집단과의 차이**로 채점한다.

### D11-2 키비주얼 초점 어휘 — 장소·부위·타 제품 명사 금지
- 02 키비주얼 KEY에는 **제품 자체, 제품의 동작, 사용자의 동작, 그 효과**를 가리키는 말만 쓴다.
- **차량 부위·장소 명사(송풍구, 대시보드, 컵홀더, 조수석, 유리 등)와 타 제품의 부품 명사(그립, 클립, 테이프 등)가 KEY에 갑자기 나오면 초점이 그 사물로 옮겨 가 키비주얼이 흐려진다.** 기존 방식과의 차이는 **동작으로** 말한다(예: 끼우지 않고 / 벌리지 않고 / 내려다보지 않고 / 붙여 두고).
- 같은 원칙을 07 KEY에도 적용하되, 07은 설명문(DETAIL)에서 부위 명사를 쓸 수 있다. 본문·09·11은 제한 없음.
- 이 원칙은 §L-2(장면 소품 어휘)를 포함해 대체한다.

### D11-3 KEY의 어휘 감도 — 배제 대상·소재 명사는 KEY에 두지 않는다 (2026-11-10 제정, 광고주 지시. 모든 영역 KEY 공통)
- **배제·비교 대상의 사물 명사**(접착제·테이프·집게·송풍구 등)는 "~ 없이"로 써도 독자에게는 그 사물이 먼저 그려진다. KEY의 그림이 피하고 싶은 사물이 된다.
- **공업·소재 명사**(접착제·본드·고무·플라스틱·금속 등)는 KEY의 온도를 떨어뜨린다. 사실을 적는 설명 줄·비교표·Q&A·제품정보에서는 정확하게 쓰고, KEY에서는 쓰지 않는다.
- 자신감·차이는 **무엇을 뺐나가 아니라 무엇을 골랐나·어떻게 되나**로. 우리 제품의 동작·구조어(다이얼로·돌려서·갖다 대면)로 말한다.
- D11-2(02·07)를 **모든 영역의 KEY**로 넓힌 것. 예: 06 `접착제 없이 붙는 데는 이유가 있습니다` → `다이얼로 고정하는 데는 이유가 있습니다`.

## D12. 03 타겟·사용 상황의 축 — '지금 쓰는 방식' (2026-11-10 제정, 광고주 컨펌 L-5)
- 03 카드의 축은 **운전 상황이 아니라 '지금 휴대폰을 두는 방식'**(§A-0의 A~E: 거치대 없음·송풍구 그립형·송풍구 마그네틱·접착식·동일 구조 실패 경험)이다. 운전 상황(출근·등하원·초행)은 사진 캡션으로만 쓴다.
- 헤더는 **거치대 미사용자까지 포괄하는 질문**으로 쓴다(예: `운전할 때 휴대폰, 지금 어디에 두세요?`). "이런 거치대 쓰시나요?"처럼 사용자만 부르는 헤더는 쓰지 않는다.
- 카드 = 사진 + **KEY 라벨(`○○ 쓰시는 분`) 먼저** + 그 아래 **서브 한 줄**(겪는 것, 12~15자 안팎, 리뷰 빈도 1위 표현을 완결된 해요체 문장으로). KEY → 서브 순서는 전 영역 공통(D10 위계)이며, 레퍼런스의 관형형 선행(`안전화를 신고 다니는 / #건설 현장`)은 쓰지 않는다. 두 줄은 예외, 세 줄 체크리스트는 쓰지 않는다. 3~4장, 거치대 없는 집단 필수(2026-11-10 개정).
- 카드 안에서 이 제품의 해결을 말하지 않는다(편의 07, 조건 09). 카드 묶음 끝에 한 줄로만 잇는다.
- 03은 방식을 호명하는 영역이므로 송풍구·그립형·접착식 같은 방식 명사를 쓸 수 있다(D11-2는 KV·07 KEY에만 적용). 1인칭 바람문·별점·구매 인증·주행 중 조작 권장은 계속 금지.

## D13. 키비주얼 KEY 작성 방법론 — 훅과 결과 (2026-11-10 제정, 광고주 컨펌 L-6. 모든 SKU 공통)

> N001에서 "KV 어필이 약하다"는 피드백을 점검해 얻은 원칙을 **다른 상품에도 쓸 수 있는 방법**으로 정리했다. 규칙이 아니라 점검 순서다. 아래 질문에 답이 나오는 KEY면 형식은 자유다.

### D13-1 KEY를 쓰기 전 두 가지를 찾는다
| 찾을 것 | 질문 | N001 예 | 다른 상품 예 |
|---|---|---|---|
| **훅(hook)** | 이 상품에서 **사진에 보이고, 경쟁 상품이 그대로 따라 말하기 어려운 것** 하나는 무엇인가? 구조·소재·동작·형태 어느 것이든 된다 | 돌려서 고정하는 다이얼 | 이어폰의 오픈형 귀걸이, 깔창의 아치 패드, 음식물처리기의 건조분쇄통 |
| **결과(payoff)** | 그 훅 때문에 **사용자에게 생기는 일** 하나는 무엇인가? 기능명이 아니라 생활의 변화 | 매일 한 손으로 붙였다 뗌 / 앞만 보고 감 | 하루 종일 음악이 끊기지 않음 / 오래 걸어도 발이 덜 아픔 / 냄새가 뚜껑 밖으로 안 나옴 |

둘 중 하나만 있는 KEY는 약하다. 훅만 있으면 설명서가 되고, 결과만 있으면 아무 상품이나 할 수 있는 말이 된다.

### D13-2 KEY를 쓴 뒤 세 가지를 점검한다
1. **스왑 테스트 두 번** — ① 같은 구조의 경쟁 상품이 그대로 써도 되는 문장인가? ② 다른 구조의 대체품(N001이면 송풍구형)이 써도 되는 문장인가? 둘 다 "아니오"가 나와야 한다. 하나만 통과하면 훅이나 결과를 바꾼다.
2. **읽는 사람의 지금** — 이 상품을 보는 사람이 지금 쓰는 방식·겪는 일(기획안 §A-0)을 떠올리게 하는 말이 있는가? 없어도 되지만, 있으면 '나한테 하는 말'이 된다. 있을 때는 **동작**으로 쓴다(D11-2: 부위·장소·타 제품 명사로 쓰지 않는다).
3. **힘의 크기** — 결과를 평서로만 쓰면 밋밋하다. **체감형 과장(D9)**을 결과 쪽에 하나 둘 수 있다(`3초`, `매일`, `한 번이면`). 보장·최상급·측정값형 수치는 여전히 쓰지 않는다.

### D13-3 형식은 상품에 맞게 고른다 (예시이지 제한이 아님)
| 형식 | 예 | 맞는 경우 |
|---|---|---|
| 훅 + 범주 | `3초 다이얼 고정 / 맥세이프 거치대` | 사진이 결과를 충분히 보여 줄 때 |
| 훅 → 결과 | `한 번 돌려 고정하면 매일 한 손` | 결과가 생활 변화로 바로 그려질 때 |
| 결과 + 범주 | `흔들리지 않는 / 편안한 사운드`(레퍼런스) | 훅이 사진에서 자명할 때 |
| 질문 | `운전할 때 휴대폰은 어디에 두세요?` | 03·04처럼 독자의 지금을 묻는 영역 |

- 용이함 형용사·의성어는 쓸 수 있다. 다만 **형용사만 둘 이상 나열**하면 결과가 아니라 장식이 되므로 피한다.
- KEY 한 줄이 훅과 결과를 다 못 담으면 **작은 차이 줄(SUB) 1줄**을 둔다. 02를 KEY만으로 끝내야 한다는 규칙은 없다(D10 위계표는 기본값일 뿐).
- 범주 명사에는 구조어를 붙여 식별을 높일 수 있다(`다이얼 락 맥세이프 거치대`).

### D13-4 하지 않는 것(최소선, 변경 없음)
보장·최상급·측정값형 수치 / 주행 중 조작 권장 / 느낌표 / 소싱명 키카피 / KV에 기능·위험·옵션을 모으는 것(가이드 A3-02).

## D14. 어휘 검증 방법론 — 통용어·약속 범위 (2026-11-10 제정, 광고주 컨펌 L-1·L-4. 모든 SKU 공통)

> N001에서 '클립'(잘못된 부품 명칭)과 '눈높이'(항상 참이 아닌 위치어)를 바로잡으며 얻은 점검법. 어떤 단어를 쓰라는 목록이 아니라, **단어를 고를 때 두 가지를 확인**하는 순서다.

### D14-1 통용어 확인 — "그 부위를 실제로 그렇게 부르는가"
- 부품·방식 이름은 **소비자 리뷰와 경쟁 상세에서 실제로 쓰는 말**로 확인한 뒤 쓴다(기획안의 리뷰 정량·경쟁 상세 분석이 1차 자료). 전문성 있어 보이는 말을 고를 때도 통용되는 범위 안에서 고른다.
- 비슷해 보이는 부위를 구분한다: 예) 집게형 거치대에서 휴대폰을 잡는 부위는 '그립', 송풍구 날개에 끼우는 부위는 '클립'. 둘을 한 이름으로 부르면 그 방식을 쓰는 독자가 어색함을 느낀다.
- 확인이 안 되는 이름은 쓰지 않고 동작으로 쓴다(`벌려서 끼우는`).
- 제품 부위에 **신체 비유어(관절·목·허리·다리)를 쓰지 않는다.** 기구 명사(힌지·암·축·조인트)나 기능 명사(각도 조절부·고정부)로 쓴다. 통용어가 신체어뿐인 경우(거치대 '헤드')만 예외. 전문어와 일반어를 포갠 겹말(`힌지 관절`)은 만들지 않는다.

### D14-2 약속 범위 확인 — "그 말이 늘 참인가"
- 위치·성능·효과를 말하는 어휘는 **어떤 차·어떤 사용자에게도 참인 범위**로 좁혀 쓴다. 예) '눈높이'는 대시보드 높이에 따라 틀릴 수 있으므로 **'시야 안'** 또는 **'내려다보지 않는'**으로. 수치·보장이 아닌 일반 어휘도 같은 점검을 한다.
- 범위를 좁혀도 이점이 남는지 본다. 남지 않으면 그 이점은 KV가 아니라 조건부로 본문에 둔다.
- 체감형 과장(D9)은 결과의 크기를 키우는 것이지 범위를 넓히는 것이 아니다. `3초 다이얼 고정`은 허용, `어느 차에서나 눈높이`는 범위 과장이라 쓰지 않는다.

### D14-3 최소 수정 원칙 (2026-11-10 추가, 광고주 지시)
- **단어가 문제면 단어만 바꾼다.** 어휘 교체(D10·D14-1·D14-2)를 이유로 KEY 문장을 새로 쓰지 않는다.
- KEY를 새로 쓰는 경우는 둘뿐이다: ① 훅·결과 구조(D13)가 없을 때 ② 뜻이 틀렸을 때. 이때도 **이전 KEY와 나란히 놓고** D13 점검(훅·결과·스왑 2중·즉시 이해)을 다시 통과해야 교체한다.
- 검수 에이전트의 "단어 2개 이내 수정" 규칙은 오케스트레이터(통합 단계)에도 똑같이 적용한다. 더 큰 수정은 작성·검수 라운드를 거친다.

## D15. 키 카피의 호흡 — 한 줄 한 호흡 (2026-11-10 제정, 광고주 컨펌 L-7. 모든 SKU 공통)
- 키 카피(KV·영역 헤더·SP KEY) **한 줄 안에서 쉼표로 절을 나누지 않는다.** "A, B." 꼴의 대구를 반복하면 기계적으로 읽힌다. 두 절이 필요하면 **줄을 바꾼다**.
- 한 줄은 한 호흡에 읽히는 길이(8~12자 안팎)로. 레퍼런스 `흔들리지 않는, / 편안한 사운드`의 쉼표는 줄바꿈 자리다.
- 본문·설명문은 자연스러운 문장이면 쉼표를 쓴다. 이 조항은 키 카피에만 해당한다.
- **동작 나열도 쉼표 없이** 잇는다: `닦고, 누르고, 끝까지 돌리고` → `닦고 누르고 끝까지 돌리기`. 세 동작 이내면 연결어미만으로 한 호흡에 읽힌다(2026-11-10 추가, 광고주 지시).

## D16. 기획서 표기 — 층은 서식으로 (2026-11-10 제정, 광고주 컨펌 L-3)
- 기획서의 소비자 카피에 `KEY / SUB / DETAIL / 라벨` 같은 **접두어를 적지 않는다**. 층은 서식으로 구분한다(굵은 줄 = KEY, 그 위 일반 줄 = SUB, 아래 문장 = 설명, 작은 글자 = 라벨·조건). §C 머리에 범례 한 줄만 둔다.
- 에이전트 산출물(후보표·채점표)도 같은 표기를 따른다.

## D17. 위험소구(04) KEY 방법론과 법령 문구 배치 (2026-11-10 제정, 광고주 컨펌 L-8 3차. 모든 SKU 공통)

### D17-1 04 KEY는 "늘 참인 사실 문장" 하나
| 점검 | 기준 |
|---|---|
| ① 늘 참인가 | 어떤 사용자·어떤 환경에도 참인 문장. 빈도어(마다·매번·자꾸)나 결과 단정 없이도 참이 되게 **문장 자체를** 고른다. 범위를 좁히는 수식어('자주는 아니어도')를 덧붙여 해결하지 않는다 |
| ② 신뢰 테스트 | 공공 안전 기관의 안내문에 그대로 실려도 어색하지 않은가 |
| ③ 즉시 이해 | 주어와 서술어가 있는 평서문(합쇼체). 명사형 조각·비유·수수께끼 금지. **명사형 종결은 KV·SP·헤더에 맞고, 인과를 설명하는 04는 서술문이 기본**(D10 위계표 04 행) |
| ④ 차이 변수와 연결 | 제품이 바꾸는 변수(N001은 휴대폰의 위치·높이)가 KEY 안이나 바로 다음 문장에 온다. 제품의 사고 예방 효과는 말하지 않는다(A3-04) |
| ⑤ 층 | 질문 줄은 선택(쓰면 짧고 비난 없이, 경험 회상형). KEY 1문장 → 설명 1~2문장(피해 가능성은 여기서 '~수 있습니다') → 준비 한 줄(명사형 가능) |
| ⑥ 과장 | 위험 쪽에는 체감형 과장을 쓰지 않는다(D9는 이점용). 독자를 위험 운전자로 규정하지 않는다 |

### D17-2 법령·안전 근거 문구는 한 곳에만
- `운전 중 휴대전화 조작은 도로교통법으로 금지되어 있습니다` 같은 **법령 인용 문장은 소비자 영역에서 한 번만**, 자리는 **11 주의사항**(또는 10 고시 하단)이다. 04·07·09에서는 반복하지 않는다.
- 04·07·09에서 안전은 **행동 지시로만** 쓴다(`경로는 출발 전에`, `변경은 주차한 뒤에`). 앞 문장이 이미 행동을 지시하면 그 근거를 설명하는 문장은 덧붙이지 않는다 — 부연으로 읽혀 힘을 뺀다.
- 일반 원칙: **앞 문장이 이미 뜻을 전했다면 근거·이유 문장을 붙이지 않는다.** 근거가 필요한 주장은 11·10에서 한 번에 모아 둔다.
- 기획안의 **근거 필드도 같다**: 04의 근거는 시선 이탈·반응 지연에 관한 공공 안전 자료만 적고, 법령은 그 문구를 쓰는 영역(11)의 근거로만 적는다. 카피에 없는 근거를 영역에 매달아 두지 않는다.

## D18. 상황·예시의 보편성 테스트 (2026-11-10 제정, 광고주 지시. 모든 영역·모든 SKU 공통)

> N001 04·05에서 "컵홀더에 둔 휴대폰으로 길 안내를 본다"는 장면을 썼다. 출처는 리뷰 1건(굿올굿즈 2026.01.24 "컵홀더에 두자니 흔들리고")이었지만, **보통 운전자는 컵홀더 속 휴대폰으로 길 안내를 보지 않는다.** 한 사람이 쓴 문장을 보편 상황으로 옮긴 오류다. 같은 실수를 막기 위해 상황·예시를 쓰기 전 아래를 점검한다.

**원칙**: 카피 속 상황·행동·예시는 **보편적이고 상식적인 사람 기준**으로 고른다. 리뷰 1~2건, 극단 사례, 작성자의 상상은 근거가 아니다(A3-04의 "부정 리뷰는 탐색의 출발점일 뿐" 원칙을 전 영역으로 확장).

| 점검 | 질문 | 통과 기준 |
|---|---|---|
| ① 상식 | 보통 사람 열에 여럿이 "나도 그래" 또는 "주변에 그런 사람 있다"고 할 행동인가? | 아니면 쓰지 않는다 |
| ② 물리적 가능 | 그 행동이 실제로 가능한가? (컵홀더 속 휴대폰 화면은 운전석에서 보이지 않는다) | 불가능·비상식이면 쓰지 않는다 |
| ③ 자료 폭 | 리뷰 정량에서 **주제 단위 건수**(예: 집게 37, 송풍구 19)가 뒷받침하는가, 아니면 특정 1건인가? | 1~2건은 장면이 아니라 '사례'로만, 그것도 05 후기 안에서만 |
| ④ 대체 표현 | 통과하지 못하면 **포괄 표현**(손 닿는 곳, 좌석 옆, 아래쪽)이나 **동작**(내려다봄, 손을 뻗음)으로 바꾼다 | — |

- 거치대 없는 운전자의 보편 행동(N001 기준): 음성 안내를 들으며 휴대폰은 조수석·무릎·도어 포켓에 두거나 손에 들고 본다. 차량 디스플레이(스마트폰 연동)를 쓰는 경우도 많다. '컵홀더에 두고 길 안내를 본다'는 보편 행동이 아니다.
- 기획안 §A-0(구매 전 행동·환경) 표의 각 행도 이 테스트를 통과한 행동만 적는다.
- 작성·검수 에이전트 브리프에 이 표를 첨부하고, 검수 '사실·리스크' 항목에서 ①②③을 본다.

## D19. 세부 설명(DETAIL)과 부품 소제 — 읽히게 쓰는 요령 (2026-11-10 제정, 광고주 컨펌 L-11. 권장이지 규칙 아님)

> 06·07·09의 설명 줄이 "눈에 안 들어온다"는 피드백에서 정리했다. **길이·문장 수는 권장치**다. 바리에이션을 막지 않도록, 지켜야 할 것은 아래 셋뿐이다.

**지킬 것(최소)**
1. **한 줄에 한 가지 사실.** 두 가지를 말하려면 줄을 나눈다.
2. **전문어는 한 줄에 하나 정도.** 부품명과 각인이 한 줄에 겹치면 일상어로 풀거나 줄을 나눈다.
3. **소제가 이미 말한 것을 설명에서 반복하지 않는다.** 설명은 사진이 못 보여 주는 것(동작 방향·조건·결과)을 더한다.

**권장(상황에 따라 벗어나도 됨)**
- 길이는 모바일 캡션 폭(28px 기준 한 줄 18~22자 안팎)을 기준으로 삼되, 뜻이 분명하면 더 길어도 된다. 문단이 필요하면 스크린을 나눈다(B-1).
- 조건절('~하면 ~됩니다')보다 **동작 → 결과** 두 문장이 읽기 쉽다.
- 추상어('밀착이 유지', '정렬')보다 **보이는 말**('붙습니다', '깨끗합니다').
- 소리 내 읽어 한 호흡에 끝나면 좋다.

**06 부품 소제**
- `부품명 — 소제`에서 소제는 **그 부위가 '하는 일'을 동작 명사형**으로(`차에 고정 / 각도 조절 / 휴대폰 부착`). 이점어(잔여물 없음·원터치)는 설명 줄이나 07로.
- 소제끼리 문법 형태를 맞추면 읽기 편하다(권장).

## D20. 셀링포인트(07) KEY와 설명 — 보편 방법론 (2026-11-10 제정, 광고주 컨펌 L-13·L-14. 모든 SKU 공통)

> N001 07을 다듬으며 얻은 점검법. 규칙이 아니라 **점검 순서**이며, 길이·문장 수는 권장치다.

### D20-1 SP 하나 = 차이 하나
- SP 한 칸은 **구매 전 행동 집단 하나(§A-0)와의 차이 하나**를 말한다. 두 이점을 한 KEY에 묶지 않는다. 부수 효과는 설명 줄로 보내거나 SP를 나눈다.
- 설명은 KEY가 말한 차이를 받친다. KEY에 없는 다른 이점을 설명에서 꺼내지 않는다.

### D20-2 스왑 테스트는 '정도·범위·조건'으로
- "경쟁품에도 그 기능이 있다"로 끝내지 않는다. **같은 정도로 되는가**를 묻는다. 기능명이 같아도 범위·조건이 다르면 차이이고 KEY가 될 수 있다(예: 각도 조절은 다 있지만 송풍구형은 날개에 매여 범위가 좁다).
- 범위 차이는 숫자 없이 **결과 어휘**(원하는·넉넉한·그대로·자유롭게)로 쓴다. 비교 대상의 제약은 설명 줄에서 부위 명사로 말할 수 있다(D11-2는 KEY에만).
- §A-0의 집단별 '겪는 것'에는 위치·동작·대기 시간뿐 아니라 **움직임·범위의 제약**도 적는다.

### D20-3 KEY 어휘
- **06 소제로 쓴 부품명을 07 KEY에 다시 쓰지 않는다.** 07의 훅은 동작·효과로, 부품명은 설명 줄에서만. (광고주가 고른 KEY는 예외)
- **힘·한계를 뜻하는 조작 노력 어휘**(끝까지·힘껏·꽉·세게)는 이점 KEY에 쓰지 않는다. 조작이 어려워 보인다.
- **몸·가구에 쓰는 동작어**(젖히다·꺾다·숙이다)는 제품 조작에 쓰지 않는다(D14-1 확장). 기울이다·돌리다·맞추다로.
- D14-2로 좁힌 정확성 교체어(시야 안 등)는 본문·조건용이다. KEY에서 밋밋하면 범위를 넓히지 않으면서 **같은 사실을 효과로** 바꿔 쓴다.

### D20-4 설명 줄의 범위
- 07은 **KEY + 이미지가 기본**이고 설명 줄은 없어도 된다(N001은 서브 텍스트 없이 간다, 2026-11-10). 쓸 때는 KEY에 없는 새 정보 한 줄(결과 장면 하나)까지. 사진·GIF가 동작을 맡는다.
- **구조는 06, 조건은 09, 안전은 11**로 보낸다. 07에는 오해를 막는 데 꼭 필요한 조건만 작은 글자 한 줄(호환 케이스, 평면 기준 같은 것).
- 설명이 두 문장을 넘으면 "KEY를 다시 쓴 것인가 / 06·09·11의 말인가"를 먼저 의심한다. 길이는 권장치(D19 준용).

## D21. 비교·선택 가이드(08) — 모바일 비교표 방법론 (2026-11-10 제정, 광고주 컨펌 L-15. 모든 SKU 공통)

> N001 08을 3스크린 행 카드에서 한 화면 ○△✕ 표로 바꾸며 얻은 점검법. A3-08(같은 기준·조건 보존·우열표 금지)을 모바일에서 실제로 읽히게 하는 방법이다.

### D21-1 한 화면
- 비교표는 **한 화면(780×1300)에 전부** 들어간다. 390px에서 스크롤 없이 모든 열이 동시에 보이는가로 검수한다. 세로로 나뉜 카드는 비교가 아니다.
- 열 ≤3(우리 + 대체 방식 2), 행 3~4. 열 머리는 **사진 썸네일 + 유형명**.
- **표 아래 글은 두지 않는다.** 범례·결론·조건·"어디서 확인" 안내 전부 제외. 이미지에 들어가는 글은 KEY와 표뿐. 조건은 09, 결론은 표 자체가 말한다.

### D21-2 셀은 ○△✕
- 셀은 **○ / △ / ✕ 기호**. 단어·문장 셀은 쓰지 않는다. 기호 색은 ○만 포인트색, △·✕는 회색(붉은 ✕ 금지).
- ○✕는 **이분 사실**(있다/없다, 된다/안 된다, 쓴다/안 쓴다)에만 쓴다. 정도·세기·속도·범위 같은 **연속량 기준은 표에 넣지 않는다**(정도 차이는 07에서 체감형으로, D20-2).
- △는 "조건이 붙어서 된다"일 때만. "조금 된다"의 뜻으로 쓰지 않는다.
- 검수 질문: "이 판정이 어떤 제품을 가져와도 같은가?" 제품마다 다르면 그 행은 뺀다.

### D21-3 기준 행
- **명사형 2~6자**(송풍구 비움·자리 이동). 질문문·부정 의문 금지.
- 모든 행에서 **○ = 좋다/된다**로 극성을 통일한다. 우리가 불리한 사실도 긍정 명사형으로 쓴다.
- 순서는 §A-0의 **다수 집단 불편 빈도순**. 소수 집단에만 닿는 기준(예: 당일 사용)은 넣지 않는다.
- 모든 기준은 **비교 축 하나**(N001은 '차에 고정하는 방식')의 결과여야 한다. 다른 축의 기준을 섞지 않는다.

### D21-4 기준 선택과 공정성
- 기준은 **우리 제품이 사실로 ○인 것** 중에서, 다른 열과 차이가 나는 것을 고른다. 우리 열이 전부 ○여도 된다. 다만 **사실과 다른 ○, 모든 열이 ○인 무의미 행**은 만들지 않는다.
- 우리 제품의 조건·한계는 표 안이 아니라 **09·11에서 보존**한다(A3-08 충족). 종합 우열 행·타사 흐림 처리·익명 비하는 계속 금지(E3).

### D21-5 열 머리 유형명
- 열 머리는 그 카테고리에서 소비자·판매처가 쓰는 **통용 유형명**(리뷰·경쟁 상세·오픈마켓 카테고리에서 확인, D14-1). 작성자가 만든 설명명(양면테이프 접착식)은 쓰지 않는다.
- 모든 열을 **같은 어미**(~형 / ~식 중 하나)로, 2~4자. 기구 설명·평가어는 붙이지 않는다(썸네일이 설명을 맡는다).
- 유형명('부착형')과 동작어('부착', D10-2)는 다른 층위다. 섞지 않는다.
- 우리 열도 유형명으로(압착형). 제품명·'이 제품' 강조어는 넣지 않고 색으로만 구분.

## D22. Q&A·주의사항(11) — 소비자의 궁금증 기준 방법론 (2026-11-10 제정, 광고주 컨펌 L-16. 모든 SKU 공통)

> N001 11을 "실패 빈도순 13문항"에서 "구매 전 5 + 사용 중 3"으로 바꾸며 얻은 점검법. 질문은 **사기 전에 실제로 묻는 것**이어야 한다.

### D22-1 두 단으로 나눈다
- **'구매 전에'**: 이 상품을 사기 전에 묻는 것. 먼저 둔다.
- **'사용 중에'**: 쓰다가 생기는 문제. 뒤에 둔다.
- **전 문항 펼침.** 접이식을 쓰지 않는다(접힌 문항은 읽히지 않는다). 단별로 한 스크린(5~6문항) 안에 들어가게 수를 맞춘다.

### D22-2 질문의 출처와 순서
| 단 | 출처 | 순서 |
|---|---|---|
| 구매 전에 | §A-0 집단별 걱정 + 상품마스터 질문 + **D18 보편성 테스트** 통과. 네 범주에서 4~6개: ① 내 환경에 되나(차·면·공간) ② 내 기기·물건에 되나(호환) ③ 계절·환경 변화 ④ 떼었을 때·옮길 때 / 없는 기능 | **걱정의 크기 순**(환경 → 호환 → 계절 → 해제·이동 → 없는 기능) |
| 사용 중에 | 부정 리뷰 빈도순 상위 3~6개 | 빈도순 |
- 부정 리뷰에서 뽑은 **증상 질문을 구매 전 단에 두지 않는다**(사기 전에 묻는 말이 아니다).
- 리뷰 1~2건짜리 희귀 질문은 넣지 않는다(D18).
- 리뷰에 자주 나오지만 질문으로 안 보이는 것(예: "다른 차로 옮길 수 있나")을 놓치지 않는다. 비슷한 질문은 한 문항에 묶는다.

### D22-3 질문·답의 형태
- 구매 전 질문은 **소비자가 문의창·검색창에 쓰는 말**로(`제 차 대시보드에도 붙을까요?`). 기능명으로 묻지 않는다. 사용 중 질문은 증상을 1인칭 그대로 둬도 된다.
- 답은 **결론 한 문장 → 조건 → 조치**. 합쇼체, 90자 안팎(권장). 09와 겹치면 09를 줄이지 말고 답을 짧게.
- **(보류) 답변이 달릴 문항은 게시 목록에서 뺀다.** 확정되면 추가한다. "확인 중입니다" 류를 싣지 않는다.

### D22-4 주의사항
- 법령·안전 최소선만(에어백·전방 시야 / 출발 전 거치·주차 후 변경 + 법령 문구 1회 / 고온·진동 재점검 / 용도 제한 / 손상·자국 기준 / 분해 금지). Q&A와 중복되는 항목(예: 충전 없음)은 뺀다.
- 책임 배제 문장("불량이 아닙니다")은 쓰지 않는다(E10).

### D22-5 N001 적용 예(참고)
구매 전(5): 제 차 대시보드에도 붙을까요? / 갤럭시나 일반 케이스도 되나요? / 여름에 떨어지지 않나요? / 떼면 자국이 남나요? 다른 차로 옮길 수 있나요? / 충전도 되나요?
사용 중(3): 자석에는 붙는데 휴대폰이 숙여지거나 떨어져요 / 화면을 더 가까이 당길 수 있나요? / 카메라나 S펜에 영향이 있나요?

## D23. 서브 텍스트의 양과 형태 — 위치가 문형을 정한다 (2026-11-10 제정, 광고주 컨펌. 모든 영역·모든 SKU 공통)

> N001 03을 "체크 3줄 → 한 줄"로 줄이고, 관형형 선행을 KEY 선행으로 바로잡으며 얻은 원칙. 03뿐 아니라 KEY 아래 서브가 붙는 모든 자리(02 보조문, 06 설명, 09 캡션)에 적용한다.

### D23-1 양
- KEY 아래 서브는 **한 줄이 기본**(12~20자 안팎, 권장치). 카드 형식이면 카드당 한 줄.
- 두 줄은 예외(두 가지 사실이 꼭 필요할 때). **세 줄 체크리스트는 1열 세로 카드에 쓰지 않는다** — 레퍼런스의 체크리스트는 큰 카드용이다.
- 여러 줄 중 하나를 고를 때는 **리뷰 빈도 1위 표현**을 남긴다. 나머지는 같은 말의 변주인 경우가 많다.
- 독자가 KEY(라벨)에서 이미 자기를 찾았다면, 서브는 "가장 많이 겪는 하나"만 떠올리게 하면 된다.

### D23-2 형태는 위치가 정한다
| 서브의 위치 | 문형 | 예 |
|---|---|---|
| **KEY 아래**(우리 기본 레이아웃, D10 위계) | **완결된 문장**(해요체·합쇼체 중 영역 문체) | `송풍구 거치대 쓰시는 분` / `에어컨 바람은 막히고 폰은 뜨거워져요` |
| KEY 위(수식 줄로 쓸 때만) | 관형형(…하는, …다니는) | `안전화를 신고 다니는` / `#건설 현장`(레퍼런스) |
- 관형형은 **뒤에 받는 명사가 있을 때만** 성립한다. KEY 아래에 관형형을 두면 문장이 끊긴 채 끝나 어색하다.
- 레퍼런스 형식을 가져올 때 **줄 순서까지 같이 가져오지 않는다.** 우리 레이아웃(KEY 먼저)에 맞춰 문형을 바꾼다.

### D23-3 점검
- 한 스크린에 글 덩어리가 셋을 넘으면(KEY·서브·그 외) 줄인다.
- 서브를 가리고 KEY와 사진만으로 뜻이 통하면 서브는 한 줄이면 충분하다.

## D24. 연구개발·설계(06) KEY — 설계도와 함께 건네는 자신감 (2026-11-10 제정, 광고주 컨펌 L-17. 모든 SKU 공통)

> N001 06 KEY를 `세 부위가 하는 일` → 기술명 → 제품 요약 → `접착제 없이…` → `다이얼로…` → `어느 한 곳도 그냥 만들지 않았습니다.`로 다섯 번 고치며 얻은 원칙. 대시보드 06 멘트 유형 중 **'기술·품질에 대한 자신감'**을 KEY가 맡고, 구조·부품 설명은 소제와 설명 줄이 맡는다.

### D24-1 KEY가 말하는 것
- 06 KEY는 구조 사진(설계도) 앞에 **"이 구조를 이렇게 만든 데는 이유가 있다"는 자신감**을 서술문 한 줄로 건넨다. 합쇼체 서술문이며 명사형 KEY가 아니다(04와 같은 예외).
- **구조 전체**를 가리킨다. 아래 부품 소제 전부가 KEY를 받아야 한다(`어느 한 곳도` → 베이스·암·헤드 셋).
- 문형 예(예시이지 제한이 아님): `어느 한 곳도 그냥 만들지 않았습니다` / `~부터 ~까지 이유가 있습니다` / `~을 ~에 맡기지 않았습니다`.

### D24-2 KEY에 넣지 않는 것
- **부품·동작 하나**(다이얼·힌지·자석). 하나를 넣으면 그 부품의 셀링포인트(07)가 되고, 나머지 소제가 KEY 밖으로 밀린다. 02 KEY의 훅을 06에서 되풀이하지도 않는다.
- **목차·예고 안내문**(`세 부위가 하는 일`, `구조를 소개합니다`)과 **의인화·업무 어휘**(하는 일·맡은 역할·담당).
- **배제 대상·소재 명사**(접착제·테이프·송풍구 — D11-3), **이점어**(잔여물 없음·원터치 — 07의 말), **제품 요약**(어떻게 붙고 거는가 — 그것은 소제·사진의 일).
- 보장·최상급·수치·느낌표(D9 최소선). 구체 개발 이력의 날조(D10-3).

### D24-3 쓸 수 있는 말
- 개발·설계 어휘(만들었다·설계했다·생각했다)는 자체 개발 이력 없이도 쓴다(D10-3).
- **스왑 테스트는 면제**한다. 06은 차별화가 아니라 이해·신뢰가 목적이므로, 같은 구조의 경쟁품이 써도 되는 말이어도 된다.

### D24-4 점검
1. 소제를 하나씩 가리키며 "KEY가 이것도 받는가"를 묻는다. 하나라도 못 받으면 KEY가 좁다.
2. KEY를 07로 옮겨 보아 어색해야 정상이다(06은 자신감, 07은 이점).
3. 사진과 함께 두었을 때 KEY가 사진을 **건네는가**(안내만 하면 실패).

## D25. 텍스트 양과 피사체 점유율 — 글이 줄면 제품이 커진다 (2026-11-10 제정, 광고주 지시. 모든 영역·모든 SKU 공통, 권장치)

> 07 서브 텍스트 삭제·06 KEY 한 줄화처럼 글을 줄여 가면, 그만큼을 **사진 속 제품이 채워야** 한다. 글이 줄었는데 제품이 작으면 스크린이 비어 보인다. 비율은 권장치이며, 컷의 목적에 따라 벗어나도 된다.

### D25-1 원리
- 한 스크린의 면적은 **텍스트 층 + 피사체 + 의도된 여백**으로 나뉜다. 텍스트 층이 줄면 **피사체가 커지고**, 여백이 커지지 않는다.
- 여백은 두 곳만 의도한다: 텍스트 자리(상단 또는 하단 한 곳)와 피사체 둘레(한 변의 10~15% 안팎). 피사체가 작고 사방 여백이 고르면 "빈 화면"의 신호다.

### D25-2 권장 점유율 (피사체의 긴 변이 프레임에서 차지하는 비율, 780px 기준)
| 텍스트 층 | 피사체 점유 | 예 |
|---|---|---|
| KEY 1~2줄만 (+작은 라벨) | **70~80%** | 06 스크린 1, 07 각 포인트, 02 |
| KEY + 서브·설명 1~2줄 | 60~70% | 03 카드, 06 접사 스크린, 09 |
| KEY + 설명 3줄 이상 또는 표 | 50~60% (표는 표가 피사체) | 04, 08, 11 |
- **접사 컷**은 부품이 프레임을 넘쳐도 된다(크롭 허용). 전체 컷은 제품이 잘리지 않게.
- **장면 컷**(03 상황, 07-1 부착 순간)은 '제품 + 손·휴대폰' 묶음이 피사체다. 환경이 더 보여도 되지만 묶음이 프레임의 절반 아래로 내려가지 않게.
- 텍스트가 사진 위에 올라갈 때(02 차콜 띠 등)는 텍스트 띠를 뺀 나머지 면적을 기준으로 잰다.

### D25-3 이미지 요청서에 적는 법
- 요청서에 **텍스트 층(KEY만 / KEY+서브 / 설명 있음)과 피사체 점유율**을 함께 적는다. 예: "KEY 1줄 + 라벨. 제품 높이 프레임 75%".
- 카피를 줄인 뒤에는 **같은 스크린의 요청서 점유율을 함께 올린다**(카피 수정 체크리스트에 포함).

### D25-4 점검
- 390px 실기기에서 피사체가 **손가락 두 마디(약 4cm)보다 작게** 보이면 키운다.
- 사진 안 텍스트와 피사체가 겹치지 않는가. 겹치면 점유율을 올리는 대신 텍스트 자리를 옮긴다.
- 한 영역 안에서 스크린마다 점유율이 들쭉날쭉하면 통일한다(접사·장면 컷 예외).
