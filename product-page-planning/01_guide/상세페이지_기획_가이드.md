## 0. 이 가이드를 쓰는 법

1. 기획안을 쓰기 전에 **§2 프로세스 0~4단계**(자료 검증 → 리서치 → 고객 → 필살기 → 오퍼)를 먼저 끝냅니다. 구성과 카피는 그다음입니다.
2. 섹션을 설계할 때는 **§3 구성 프레임**에서 뼈대를 고르고, **§5 카피 툴킷**으로 문장을 씁니다.
3. 제출 전에 **§9 검수 점수표**에서 80점 이상인지 확인합니다. **§8 법·플랫폼** 항목은 하나라도 걸리면 반려합니다.
4. 기획안은 **§10 산출물 양식**대로 작성합니다. 대시보드 기획안 필드(message·copy·visual·evidence·productionBrief·missingFacts)와 1:1로 대응합니다.

## 2. 기획 프로세스 (0~9단계)

> 단계마다 **산출물**이 있어야 다음 단계로 넘어갑니다.

### 0단계: 자료 신뢰도 점검
- [ ] 소싱 · 자료수집 · 상품마스터의 **값 충돌**(치수·소재·모델명·원가·색상·구성품)을 표로 정리합니다.
- [ ] 각 값에 출처 등급을 매깁니다: 실측·공급사 서면 > 판매처 사양 > 해외 유통 문구 > 광고 문구.
- [ ] **기획에 쓸 수 없는 문구**를 표시합니다. 검증 안 된 수치(예: 96lbs, N52, 360°)와 타 판매처 후기가 여기에 해당합니다.
- **산출물**: `자료_신뢰도_점검.md` (확정 / 확인 필요 / 사용 금지 3구분)

### 1단계: 리서치
- [ ] 같은 카테고리 상위 5~10개 상세페이지를 **전체 캡처**합니다(GoFullPage). 피그마에 나란히 놓고 블록 순서를 표로 만듭니다 [YT01].
  - 네이버쇼핑 › 쇼핑BEST › 많이 구매한 상품에서 고릅니다.
  - 쿠팡은 리뷰 많은 상품과 PB 상품을 봅니다 [YT06].
- [ ] 경쟁사 리뷰를 수집합니다. **1~3점 리뷰는 불안 목록**, **4~5점 리뷰는 구매 이유와 고객 언어**로 씁니다 [M-S20][C-S72].
- [ ] 유튜브 비교 리뷰와 숏폼 광고를 장면 단위로 분석합니다. 소비자 선택 기준과 후킹 패턴을 뽑습니다(Higgsfield `video_analysis`).
- [ ] 가격 맵을 만듭니다. 최저가(다이소 등)부터 프리미엄까지, **구성품 수량 기준으로 단가를 환산**합니다.
- [ ] 고시 품목, 인증 대상, 상표 리스크를 확인합니다(§8).
- **산출물**: 경쟁 블록표, VOC 표(원문·태그·빈도), 가격 맵, 메시지 맵

### 2단계: 고객 정의
- [ ] "필요한 사람"이 아니라 **강한 욕구와 즉시 해결 필요가 함께 있는 사람**으로 타깃을 좁힙니다 [YT03]. (예: "운전자" X → "갤럭시로 매일 내비를 켜는 출퇴근 운전자" O)
- [ ] 페르소나는 1~2개로 만듭니다. 각 페르소나에 일상, 고민, 망설이는 이유, 사용 타이밍을 리뷰 문장으로 채웁니다 [YT05].
- [ ] **JTBD 한 문장**: "~할 때 / ~하고 싶다 / 그래야 ~할 수 있다" [C-S18].
- [ ] **인지 단계**(Schwartz 5단계)를 판정합니다. 상세페이지 방문자는 보통 해결책 인지~제품 인지 단계입니다. 광고 소재는 문제 인지 단계용으로 따로 만듭니다(§5-2).
- **산출물**: 페르소나 카드, 구매 장벽 목록(→ FAQ와 신뢰 블록 재료)

### 3단계: USP와 필살기
- [ ] 소구점 후보를 모두 적고 **FAB**(특징 → 장점 → 이점)으로 바꿉니다 [C-S9].
- [ ] 다음 3가지 기준으로 **필살기 1개**를 고릅니다 [YT04].
  1. 고객의 1순위 고민을 해결하는가
  2. 경쟁 상품의 메시지와 겹치지 않는가
  3. 실물로 증명할 수 있는가(영상·사진)
- [ ] 보조 USP는 2개 이내로 둡니다. 나머지는 사양표나 FAQ로 내립니다.
- [ ] 각 USP 옆에 **증거 1개**를 짝지웁니다. 증거가 없으면 탈락시키거나 표현을 낮춥니다.
- **산출물**: USP 매트릭스(주장 / 고객 이점 / 증거 / 증거 상태)

### 4단계: 오퍼 설계 (본체가 같은 상품일수록 가장 중요)
본체를 차별화할 수 없는 기성 상품이라면 **경쟁력은 오퍼에서 나옵니다**.
- [ ] **구성품**: 고객 불만을 해결하는 부속을 넣습니다(예: 링 여분, 보조패드, 클리닝 패드, 한글 설치 카드).
- [ ] **묶음**: 1개 / 2개(차 2대, 차+책상) / 가족용.
- [ ] **리스크 제거**: 교환·환불 조건과 보증 기간. 신지모루가 차량용 A/S 1년을 내세우는 것이 기준점입니다 [K].
- [ ] **가격**: 가격 맵 안에서의 위치를 정합니다. 마진은 판매가 − 원가 − 수수료 − 물류비 − 광고비로 계산합니다.
- [ ] **혜택 문장**: "혜택 없는 카피는 팔 생각이 없는 카피"입니다 [YT08]. 구성 이득을 숫자로 보여줍니다.
- **산출물**: 옵션표, 손익표, 보증 정책 문안

### 5단계: 유형 선택과 섹션 구성
- [ ] §3에서 유형(문제해결형 / 디자인강조형 / 스펙·호환확인형)과 플랫폼 문법을 고릅니다.
- [ ] **머리 → 몸통 → 증명 → 마무리** 뼈대에 섹션을 배치합니다.
- [ ] 첫 3스크롤에는 **공감(문제) → 해결 → 신뢰 지표**를 둡니다 [M-S9]. "구매 결정이 3스크롤 이내"라는 수치는 와디즈 주장입니다 [M-S5].
- **산출물**: 와이어프레임 표(섹션 번호 / 역할 / 핵심 메시지 / 매체)

### 6단계: 카피
- [ ] 섹션마다 **결론형 소제목 1줄 + 보조 1~2줄**로 씁니다(레이어케이크 패턴 대응) [M-S41].
- [ ] 형용사는 수치나 장면으로 바꿉니다. 단, 수치는 실측 근거가 있을 때만 씁니다.
- [ ] 헤드라인은 3~5개 후보를 만들고 **4U**(유용·긴급·독특·구체) 점수로 거릅니다 [C-S11].
- [ ] 고객 언어(리뷰 원문)를 헤드라인 재료로 씁니다. 단, **타 판매처 후기를 자사 후기처럼 게재하지 않습니다**(§8).
- **산출물**: 섹션별 카피, 헤드라인 A/B 후보

### 7단계: 비주얼·제작 브리프
- [ ] 이미지만 봐도 내용이 추측되어야 합니다. 헤드라인을 안 읽어도 이해되는 직관적 이미지를 씁니다 [YT02].
- [ ] 동작은 GIF와 짧은 영상으로 보여줍니다(탈부착, 다이얼 잠금, 접이) [YT02][YT12].
- [ ] 크기 비교 컷(손·폰 옆)을 넣습니다. Baymard 조사에서 사용자 42%가 이미지로 크기를 가늠했습니다 [M-S15].
- [ ] 촬영 리스트, 연출과 실제의 구분, 금지 연출(주행 중 조작 장면 등)을 적습니다.
- **산출물**: 섹션별 제작 브리프, 촬영 리스트

### 8단계: 검수
- [ ] §8 법·플랫폼 체크리스트(하나라도 걸리면 반려)
- [ ] §9 검수 점수표(80점 이상)
- [ ] 실기기에서 확인합니다(390px 폭, 글자 크기, 대비) [M-S10].

### 9단계: 테스트 계획
- [ ] A/B 후보를 정합니다. 1순위는 첫 화면 헤드라인과 대표 이미지, 2순위는 오퍼 표기입니다.
- [ ] KPI: 상세 도달률, 구매 전환율, 반품 사유, 리뷰의 불만 키워드.
- [ ] 광고 소재는 본문을 고정하고 **첫 3초 훅만 3~5개 변형**합니다 [C-S60].

## 3. 구성 프레임

### 3-1. 기본 뼈대: 머리 → 몸통 → 증명 (+ 마무리)  [YT01][YT05][YT08]

| 블록 | 역할 | 들어갈 것 | 체크 |
|---|---|---|---|
| **머리** (첫인상) | 썸네일에서 본 바로 그 상품이 여기 있음을 1초 안에 확인시킨다 | 혜택·보증 배너(짧게) → 제품 즉시 노출(한 줄 결론 + 대표컷) → 사회적 증거(리뷰 수·평점·판매량, **있을 때만**) | 첫 화면에 제품이 보이는가 / 무엇이고 왜 필요한지 한 줄인가 |
| **몸통** (행동 버튼) | "왜 사야 하나"를 심는다 | 고객 관점 질문("이런 적 있으시죠?") → 결핍과 원인 → 우리 제품의 해결 방식 | 질문이 고객 언어인가 / 원인과 해결이 이어지는가 |
| **증명** | 강점을 하나씩 근거로 증명한다 | 강점 1·2·3. 각 강점은 시연 GIF/영상 + 짧은 카피 + 조건 | 강점마다 증거가 있는가 |
| **마무리** | 마지막 의심을 지우고 결제로 보낸다 | 호환·사양 → 구성·옵션 → FAQ → 보증·교환 → (CTA) → 고시 → 브랜드 | 반론 질문 상위 5개에 답했는가 |

인지도가 높은 브랜드는 몸통을 줄여도 됩니다. **무명 셀러일수록 몸통과 증명을 두껍게** 합니다 [YT01].

## 4. 첫 화면과 썸네일 규칙

### 4-1. 첫 화면(히어로) 3요소  [YT07][YT05][YT10]
1. **고민을 콕 집는 헤드라인** 또는 **결론형 한 줄**. 고객이 먼저 스캔하는 건 이미지가 아니라 공감 단어입니다.
2. **헤드라인과 짝을 이루는 이미지**. 예쁜 제품컷만으로는 부족합니다. 실제 사용 장면이나 전후 장면을 씁니다.
3. **WHAT / WHY / HOW**가 몇 단어 안에 보여야 합니다. 무엇을 주는지, 왜 원해야 하는지, 어떻게 얻는지입니다.
- 첫 화면을 과밀하게 만들지 않습니다. 할인 배너가 상품 이미지를 아래로 밀어내면 안 됩니다 [YT09].
- 여러 기기 폭(390px / 360px)으로 미리보기합니다 [YT09].

### 4-2. 썸네일(대표·추가 이미지)
- **대표 이미지**: 제품이 화면의 60% 이상을 차지하게 합니다. 실사용 맥락(차량)이 보여야 하고, 텍스트는 플랫폼 정책 범위 안에서만 씁니다.
- **추가 이미지 4~8장 순서**: 핵심 장면 → 필살기 시연 → 구성품 → 호환(갤럭시·아이폰) → 크기 비교 → 설치면 조건.
- 비충전 상품처럼 오해가 생길 수 있는 속성은 추가 이미지 안에서 명시합니다 [K].

## 10. 기획안 산출물 양식

대시보드 `salesWorkspace.plan` 구조와 맞춘 양식입니다.

```
# [SKU] 상세페이지 기획안 vX.Y
## 0. 한 장 요약 — 타깃 / 필살기 / 오퍼·가격 / 메인 헤드라인 / 유형·플랫폼
## 1. 자료 검증 결과와 선결 과제
## 2. 시장·경쟁 (가격 맵, 메시지 맵, 빈 축)
## 3. 고객 (페르소나, JTBD, 인지 단계, 장벽→해소 매핑)
## 4. 포지셔닝·USP 매트릭스
## 5. 오퍼 설계 (옵션표, 손익, 보증)
## 6. 상품명·키워드·썸네일
## 7. 상세페이지 섹션 설계 — 섹션마다:
   - id / 역할(머리·몸통·증명·마무리)
   - message: 이 섹션이 고객 머리에 남길 한 문장
   - copy: 소제목 / 보조 / 라벨
   - visual: 장면·구도·매체(image/gif/video)
   - evidence: 근거와 출처 코드
   - productionBrief: 촬영·편집 지시, 금지 연출
   - missingFacts: 제작 전에 확정할 값
## 8. 증거 제작 계획 (자체 테스트 프로토콜)
## 9. 광고·숏폼 소재
## 10. FAQ
## 11. 법·표기 점검 결과
## 12. 테스트·KPI 계획
## 13. 실행 체크리스트 (담당·기한)
```
