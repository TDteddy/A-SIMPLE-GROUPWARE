# 카피 작성·검수 2에이전트 프로세스 (2026-11-10 제정)

> 기획안·카피를 **만드는 역할**과 **검수해 채택하는 역할**을 분리한다. 같은 에이전트가 만들고 고르면 후보가 좁아지고 자기 판단을 확인하는 방향으로 기울기 때문이다. 오케스트레이터(메인 세션)는 브리프를 쓰고, 두 산출물을 받아 기획안에 반영한다.

## 역할

| 역할 | 하는 일 | 하지 않는 일 | 입력 | 산출물 |
|---|---|---|---|---|
| **Writer(작성)** | 단위별 후보를 넓고 다양하게 생성(키 카피 5~8안, 보조문 3~4안), 각 후보의 의도·리스크 메모, 추천 1순위 표시 | 채택·탈락 결정, 가이드 해석 변경, v2 계열 열람 | 현행 기획안(§R 형식·§A-0 행동·§A-2 규칙·§C 기준선), 리뷰 정량, 벤치마킹 반영안, copywriting 스킬 | `copy-run-v3/A_candidates.md` |
| **Reviewer(검수·채택)** | 후보를 기준표로 채점, 단위별 1안 채택 + 차순위 1안, 탈락 이유 기록, **우려 후보는 사람 검토 표로 보존**, 채택안에 최소 수정 제안, 가이드 12문항·E1~E12 교차 점검 | 새 후보 창작(수정 제안은 단어 2개 이내), 기준 완화 | A_candidates + 가이드 A2·A3·A6 + E1~E12 + §R 형식 + §A-2 규칙 + copy-editing 스킬 | `copy-run-v3/B_decisions.md` |
| **Orchestrator(통합)** | 브리프 작성, 두 산출물 대조, 기획안 반영(버전 업), 반영하지 않은 채택안이 있으면 이유 기록 | 자기 후보를 끼워 넣기 | A, B | 기획안 vN.N + `copy-run-v3/C_merge_log.md` |

## 검수 기준표 (Reviewer가 모든 후보에 적용, 각 0~2점)

| 기준 | 2점 | 0점 |
|---|---|---|
| 즉시 이해 | 한 번 읽고 뜻이 잡힘 | "무슨 소리지" |
| 차이 | 구매 전 행동(A~E) 중 하나와의 차이가 문장에 보임 | 제품 없이도 성립 |
| 레퍼런스 형식 | 수식 줄 + 이점 명사 / 해당 영역 형식 일치 | 대구·비유·부품명 |
| **어필(2026-11-10 추가)** | 당연한 장점이 아니라 **바꿀 이유**가 보임(기존 거치대 사용자에게도) | 모든 거치대에 해당하는 말, 밋밋한 사실 서술 |
| 자연스러움 | 소리 내 읽어 걸리지 않음 | 억지 명사형·번역체 |
| 글자 수 | 수식 8~12 / 명사 6~10 / 보조 40자 이내 | 초과 |

- 6항목(즉시 이해 / 차이 / 레퍼런스 형식 / 자연스러움 / 글자 수 / 어필) 합계 **10점 이상** 채택 후보, 동점이면 '어필' → '차이' 순. 8점 미만은 탈락.
- 하드 탈락(점수 무관): 주행 중 조작 권장, 느낌표. **표현 수위(과장·오인)는 판정하지 않는다(가이드 D9 3차).**
- **사람 검토(Human Review) 표**: 검수자가 채택하지 않았지만 어필이 강한 후보(합계 9점 이상)를 점수·한 줄 의견과 함께 올려 광고주가 고를 수 있게 한다. 표현 수위에 대한 의견은 적지 않는다.

## 핸드오프 규칙
1. Writer는 Reviewer 산출물을 보지 않는다(순서상 불가). Reviewer는 Writer의 '추천 1순위'를 **채점 후에만** 확인한다(앵커링 방지 — 채점표를 먼저 채우고 추천 표시를 본다).
2. Reviewer가 모든 후보를 탈락시킨 단위는 "재작성 요청"으로 Writer에게 되돌린다(브리프에 탈락 이유 첨부). 최대 2회.
3. Orchestrator는 채택안을 그대로 반영한다. 바꾸면 `C_merge_log.md`에 이유를 적는다.
4. 두 에이전트 모두 v2 계열 문서는 열지 않는다.

## 이 프로세스의 한계
- 두 역할 모두 같은 모델이라 어휘 취향이 겹칠 수 있다. Writer 브리프에 어휘 다양화 지시를 넣고, Reviewer 기준에 '자연스러움'을 따로 둔다.
- Reviewer의 채점은 가이드·형식 일치도이지 전환율 예측이 아니다. 최종 판단은 사람(광고주)이 한다.
