# 문제해결형 상세페이지 기획안 가이드 (보편판 v1.1, 2026-11-10)

> **성격**: 대시보드 가이드라인(13영역 · 6필드 · 검수 12문항)을 기준 문서로 두고, N001 기획안 v3.0→v3.9를 만들며 참고·제정한 **모든 지침**(상세페이지_기획_가이드 Part A·B·보이스·D6~D26, 2에이전트 프로세스, 기획안 §S)을 전수 검토해 **다른 상품에도 그대로 쓸 수 있게** 일반화한 것이다. 검토 결과와 반영 위치는 부록 C.
> **위계**: 대시보드 가이드라인 원문(Part A) > 이 가이드 > 보조 방법론. 충돌하면 항상 대시보드 원문을 따른다. 광고주 결정으로 원문을 바꾼 항목(후기 가공 게재·개발 어휘·'맥세이프' 자유 사용·표현 수위 판정 제외)은 해당 절에 표시했다.
> **읽는 법**: 각 항목은 **최소선**(지키지 않으면 게시 불가)과 **권장**(상황에 따라 벗어나도 됨)으로 나뉜다. 글자 수·비율·개수는 전부 권장치다. 규칙보다 **점검 질문**으로 썼으니, 질문에 답이 나오면 형식은 자유다.
> **적용 범위**: 문제해결형 상세페이지 전체(기획안 작성 → 모바일 스크린 설계 → 이미지 생성 → 조립 스튜디오 표준 템플릿 적용 → 검수).

## 1. 시작 전 — 소비자의 상황과 배경부터

### 1-1 구매 전 행동·환경 표 (최소선)
- 카피를 쓰기 전에 **"이 제품을 보는 사람이 지금 무엇을 쓰고, 무엇을 겪는가"**를 리뷰·조사 자료로 표로 만든다. 열: 지금 하는 방식 / 어떻게 쓰는가 / 불편(리뷰 표현) / 이 제품으로 바뀌는 동작 / 근거(건수). 이 표가 없으면 키 카피를 쓰지 않는다.
- 집단은 **대체 방식별**로 나눈다(예: 미사용 · 유형 A · 유형 B · 같은 구조의 타사 제품 실패 경험). 비율은 리뷰 키워드 빈도이며 시장 대표값이 아니라고 적어 둔다.
- 이점은 **다수 집단이 겪는 것과의 차이**에서 고른다. 소수 집단에만 닿는 차이, 모든 제품에 해당하는 당연한 장점은 키비주얼에 두지 않는다.
- 각 집단의 '겪는 것'에는 위치·동작·대기 시간뿐 아니라 **움직임·범위의 제약**도 적는다(정도 차이가 셀링포인트가 된다).

### 1-2 보편성 테스트 (최소선, 전 영역)
카피 속 상황·행동·예시는 **보편적이고 상식적인 사람 기준**으로 고른다. 리뷰 1~2건, 극단 사례, 작성자의 상상은 근거가 아니다.

| 점검 | 질문 | 통과 못 하면 |
|---|---|---|
| 상식 | 보통 사람 열에 여럿이 "나도 그래"라고 할 행동인가 | 쓰지 않는다 |
| 물리적 가능 | 그 행동이 실제로 가능한가 | 쓰지 않는다 |
| 자료 폭 | 주제 단위 건수가 뒷받침하는가, 특정 1건인가 | 1~2건은 후기 안의 '사례'로만 |
| 대체 | — | 포괄 표현(손 닿는 곳·옆자리)이나 동작(내려다봄·손을 뻗음)으로 바꾼다 |

### 1-3 명칭과 첫 화면 결정 (최소선, 대시보드 A0 1단계·A3-02)
- 소싱명 / 일반 카테고리명 / 판매용 고유명 / 승인 상태를 구분해 적는다. **소싱명·일반명·검색 키워드 조합은 키카피로 쓰지 않는다.** 판매명 미정이면 무카피 화보형이거나 확인된 매력 하나를 담은 짧은 카피(범주 명사는 허용: `맥세이프 거치대`)로 간다. 가칭·SKU 코드는 소비자 화면에 쓰지 않는다.
- 오해를 막는 핵심 조건(비충전·설치면 기준 등)은 키비주얼 가까이에 작은 라벨로 둔다. 표준 템플릿에 라벨 슬롯이 없으면 제품정보·Q&A로 보낸다(7-1).

### 1-4 근거의 종류와 말할 수 있는 범위 (최소선, 대시보드 A0-1·B4)
| 근거 | 쓸 수 있는 말 | 넘지 않는 선 |
|---|---|---|
| 확인된 구조·동작 | 그 동작이 가능하다는 사용 방식 | 하중·수명·유지 시간은 별도 근거 |
| 실제 사용자 경험 | 그 사람의 경험(원문 또는 가공 규칙 4-4) | 모든 조건의 성능·대표 동기·만족률로 확대하지 않음 |
| 아직 안 한 실험 | 내부 제작 요청과 판정 기준 | 결과 카피·'검증 완료' 표시 보류 |
| 일반 위험 자료 | 위험 경로와 준비 필요성 | 제품의 예방 효능으로 바꾸지 않음 |
- 기성 상품은 시험성적서가 없으므로 **조건을 표기한 자체 시험 영상**이 결과 주장의 사실상 유일한 1등급 증거다. 시험 설계 전에 "이 결과가 어떤 문구를 바꾸는가"를 먼저 적고, 바꿀 문구가 없는 시험은 하지 않는다. 실험 GIF 요청은 대시보드 8항목 양식(검증 질문·표본·환경·절차·촬영·관찰·편집·게시 조건)으로.
- AI 생성 이미지·영상은 **연출 시안**이지 증거가 아니다. 판매자 사양값은 출처·확인 수준을 표기하고, 충돌하는 값은 실측 전 소비자 원고에 쓰지 않는다.

### 1-5 보류 항목과 가정값 운용 (최소선, 대시보드 B9)
- 미확정 값(치수·소재·구성·보증·정착 시간)은 추정해 채우지 않고 `(보류: 항목코드)`로 표시한다. 기획안 머리에 **보류 레지스터**(번호 / 영역 / 내용 / 교체 조건 / 담당)를 두고, 확정되면 레지스터와 해당 영역·연결된 Q&A·고시만 고친다.
- 가정값은 **기획 초안까지만** 허용하고 조판·게시에는 넘기지 않는다. (보류) 답변이 달릴 Q&A 문항은 게시 목록에서 뺀다. "확인 중입니다"를 소비자 화면에 싣지 않는다.
- 기획 · 자료 확보 · 소비자 제작 · 검토·게시는 서로 다른 완료 상태다. 형식 검사만으로 검수 완료를 보고하지 않고, 게시 전 모바일 실물 검수는 생략할 수 없다.

## 2. 어휘 준비

### 2-1 용어표 만들기 (권장 방법)
- 그 카테고리에서 **리뷰·경쟁 상세·오픈마켓 카테고리명**에 실제로 쓰이는 말을 모아 '일반어 → 통일 표기' 표를 만든다. 전문성은 **무거운 한자어가 아니라 정확한 구분**에서 온다. 무겁게만 바꾼 말(예: 설치→장착)은 되돌린다.
- 두 가지만 확인한다. **① 통용어**: 그 부위·동작을 실제로 그렇게 부르는가. **② 약속 범위**: 그 말이 늘 참인가(제품이 항상 그 상태를 만들지 못하면 범위를 좁힌 말로).
- **동작어 구분표**: 소비자가 쓰는 동작어 3~5개를 뽑아 한 동작에 한 단어를 고정한다(예: 설치 / 고정 / 부착 / 거치).
- 제품 부위에 **신체 비유어**(관절·목·허리)를 쓰지 않는다. 기구 명사(힌지·암·축)나 기능 명사(각도 조절부)로. 통용어가 신체어뿐이면 예외(헤드).
- **최소 수정 원칙**: 광고주가 좋다고 한 카피는 어휘 하나만 바꾸고 문형은 유지한다. 지침이 바뀌어도 확정 카피를 통째로 다시 쓰지 않는다.

### 2-2 KEY에서 피하는 어휘 (최소선)
- **배제·비교 대상의 사물 명사**(경쟁 방식의 부품·소재): "~ 없이"로 써도 독자에게는 그 사물이 먼저 그려진다.
- **공업·소재 명사**(접착제·본드·고무·금속): 설명 줄·비교표·Q&A에서는 정확히 쓰고 KEY에서는 쓰지 않는다.
- **장소·부위 명사**(차량 부위, 가구, 방): 키비주얼·셀링포인트 KEY에서는 초점이 그 사물로 옮겨 간다. 차이는 **동작**으로 말한다(끼우지 않고 / 벌리지 않고 / 내려다보지 않고).
- **조작 노력 어휘**(끝까지·힘껏·꽉)와 **몸·가구의 동작어**(젖히다·꺾다·숙이다)는 이점 KEY에 쓰지 않는다.
- 자신감·차이는 **무엇을 뺐나가 아니라 무엇을 골랐나·어떻게 되나**로 말한다.

### 2-3 쓸 수 있는 어휘 (권장)
- **용이함 형용사**(쉬운·편한·간편한)와 **의성어**(착·툭)는 선택지다. 쓸 때는 구체 동작·결과와 붙인다. 형용사만 둘 이상 나열하면 장식이 된다.
- **개발·설계의 말**(만들었다·설계했다·고민했다)은 자체 개발 이력이 없어도 쓴다. 지어내지 않는 것은 **구체 이력**(연구 기간·연구소·특허·시험 수치·등록증의 성능 확대)뿐이다.
- **체감형 과장**(3초·매일·한 번이면)은 이점 쪽에 하나 둘 수 있다. 보장·최상급·측정값형 수치는 쓰지 않는다. **표현 수위의 판정은 사람(광고주)의 몫**이며 검수 에이전트는 "과장이다·오인된다"를 감점 사유로 쓰지 않는다.

### 2-4 브랜드 보이스 프로필 (권장)
- 브랜드 공식 문장 10개 안팎에서 **한 문장 정의 / 하세요 / 하지 마세요 / 쓸 말 / 피할 말 / 리듬**을 뽑아 둔다. 영역별 어투(3-5)와 검수 '자연스러움' 항목의 기준이 된다.
- 공통 최소선: 감탄사·느낌표·"~해보세요!" 미사용, 최상급·형용사 겹치기 금지, 기능 나열·기술 용어 선두 금지, 세 문장 넘는 설명 금지. 피할 말(강력·완벽·혁신·최고·어디서나)은 용어표에 함께 둔다.

## 3. 카피 공통 원칙

### 3-1 위계 (최소선 두 가지)
- 모든 스크린에 **간단명료한 KEY 1줄**이 있다.
- 설명(DETAIL)은 **2문장 이내**.
- 세 층(KEY·SUB·DETAIL)을 모든 영역에 강제하지 않는다. 영역별 기본 구조는 4절 표. 기획서에는 접두어(KEY/SUB)를 적지 않고 서식으로 구분한다.

### 3-2 KEY의 문형 (권장)
- 기본은 **명사형, 한 줄 한 호흡**(8~12자 안팎). 쉼표로 절을 나누지 않는다. 두 절이면 줄을 바꾼다. 동작 나열도 쉼표 없이 `~고 ~고 ~기`.
- **서술문 예외**: 인과를 설명하는 위험소구(04)와 자신감을 건네는 설계(06)는 합쇼체 서술문이 기본.
- 질문형은 독자의 지금을 묻는 영역(03·04)에.

### 3-3 설명 줄 요령 (권장)
- 한 줄에 한 가지 사실. 전문어는 한 줄에 하나 정도. 소제가 말한 것을 설명에서 반복하지 않고, **사진이 못 보여 주는 것**(동작 방향·조건·결과)을 더한다.
- 조건절(`~하면 ~됩니다`)보다 **동작 → 결과** 두 문장. 추상어(밀착 유지·정렬)보다 **보이는 말**(붙습니다·깨끗합니다).
- 앞 문장이 이미 뜻을 전했다면 **근거·이유 문장을 덧붙이지 않는다**(부연은 힘을 뺀다). 근거는 Q&A·고시에 모은다.

### 3-4 서브 텍스트의 양과 형태 (권장)
- KEY 아래 서브는 **한 줄이 기본**(12~20자). 세 줄 체크리스트는 1열 카드에 쓰지 않는다. 여러 줄 중 하나를 고를 때는 **리뷰 빈도 1위 표현**.
- **위치가 문형을 정한다**: KEY 아래는 완결 문장, KEY 위(수식 줄)만 관형형. 레퍼런스 형식을 가져올 때 줄 순서까지 가져오지 않는다.

### 3-5 어투 통일 (최소선)
- KEY 명사형 / 설명·답·고지 합쇼체 / 타겟 서브·후기 해요체 / 정보 행 명사형 개조식. **같은 영역 안에서는 같은 어미.** 소비자 카피의 지칭어(휴대폰 등)는 하나로 통일하고 후기 원문·법령 인용만 예외.
- 느낌표 미사용, 주행 중(사용 중 위험 행동) 조작 권유 금지는 전 영역 최소선.

### 3-6 카피 발상 도구 (권장, 영역 원고의 틀이 아님)
- FAB(특징→장점→이점)는 07 내부 정리에, JTBD(상황→동기→결과)는 03과 선정 이유 한 문장에, VOC→카피 6단계는 03·07·11 재료에 쓴다. PAS·Schwartz·4U·헤드라인 템플릿은 **광고 소재** 전용이며 상세 영역을 문제 반복이나 품질 점수로 채우는 데 쓰지 않는다(대시보드 A4-9: 줄 수·글자 수·대구·SP 개수는 품질 점수가 아니다).
- 오픈소스 스킬 게이트(3질문·Now-you-can·AI 티·Seven Sweeps·SUCCESs·KV 식별·FAQ 3관문·레버 장부·브랜드 리뷰)는 **후보를 거르는 보조 검사**다. 스킬의 CTA 강화·긴급성·"지금 사야 할 이유"는 쓰지 않고, 스왑 실패는 공통 구조 상품에서는 감수한다.
- **AI 티 금지 패턴**: 대조 리빌("~가 아닙니다, ~입니다"), 부정 나열, 쌓기, 자문자답, 콜론 리빌. 쉼표 대구(3-2)와 같은 취지.

## 4. 영역별 방법론

**13영역의 구매 판단 질문** (대시보드 A2 — 영역마다 '앞에서 없던 새 정보'를 하나씩 더한다)
01 누구에게서 사는가 → 02 무엇을 먼저 보고 기억할 것인가 → 03 내게 언제 필요한가 → 04 준비하지 않으면 어떤 위험을 만나는가 → 05 실제 사용·평가 자료는 무엇을 말하는가 → 06 무엇이 그 기능을 가능하게 하는가 → 07 사용할 때 무엇이 좋아지는가 → 08 왜 이 제품·옵션인가 → 09 무엇을 받고 어떻게 쓰는가 → 10 필수 정보가 맞는가 → 11 남은 문제는 어떻게 확인·조치하는가 → 12 이 브랜드가 지키는 기준은 → 13 내부 제작(소비자 본문 아님). 순서는 고정이며, 모든 제목을 같은 공식("불편하지 않으세요? / 이제 해결하세요")으로 만들지 않는다.

|---|---|---|
| 02 키비주얼 | KEY(+조건 라벨). 훅·결과를 한 줄에 못 담으면 SUB 1줄 | 훅 1 + 결과 1, 스왑 테스트 2중 |

| 11 Q&A | 구매 전 / 사용 중 두 단, 전 문항 펼침 | 사기 전에 실제로 묻는 말인가 |

### 4-1 키비주얼(02): 훅과 결과
- 쓰기 전에 둘을 찾는다. **훅** = 사진에 보이고 경쟁 상품이 따라 말하기 어려운 것 하나. **결과** = 그 훅 때문에 사용자에게 생기는 생활의 변화 하나. 하나만 있으면 설명서(훅만)나 아무 상품의 말(결과만)이 된다.
- 쓴 뒤 셋을 점검한다. ① 스왑 2중(같은 구조 경쟁품 / 다른 구조 대체품이 그대로 써도 되는가 → 둘 다 '아니오') ② 읽는 사람의 지금이 떠오르는가(있다면 동작으로) ③ 결과 쪽에 체감형 과장 하나.
- 형식은 자유: 훅+범주 / 훅→결과 / 결과+범주 / 질문. 범주 명사에 구조어를 붙여 식별을 높일 수 있다.

### 4-2 타겟(03): 지금 쓰는 방식
- 카드의 축은 **사용 상황이 아니라 '지금 그 일을 어떻게 하고 있는가'**(행동표의 집단). 상황(출근·등하원)은 사진 캡션으로만.
- 헤더는 **미사용자까지 포괄하는 질문**. 카드 = 사진 + KEY 라벨(`○○ 쓰시는 분`) + 서브 한 줄(겪는 것, 완결 문장). 카드 안에서 이 제품의 해결을 말하지 않는다.
- 03은 방식을 호명하는 영역이라 방식 명사(유형명)를 쓸 수 있다.

### 4-3 위험소구(04): 늘 참인 사실 문장
- KEY는 **어떤 사용자·환경에도 참인 평서문 하나**. 빈도어(마다·자꾸)나 결과 단정 없이 참이 되게 문장 자체를 고른다. 공공 안전 기관 안내문에 실려도 어색하지 않은가로 신뢰 테스트.
- 제품이 바꾸는 변수가 KEY나 다음 문장에 온다. 제품의 사고 예방 효과는 말하지 않는다. 위험 쪽에는 과장을 쓰지 않고 독자를 위험 사용자로 규정하지 않는다.
- **법령 인용은 소비자 영역에서 한 번만, 자리는 Q&A 주의사항.** 04·07·09의 안전은 행동 지시로만(`변경은 주차한 뒤에`). 기획안의 근거 필드도 같은 원칙(카피에 없는 근거를 매달지 않는다).

### 4-4 후기(05): 구매를 자극하되 사람이 쓴 것처럼
- **선정**: 3~5장. ① 전환 서사 ② 구체 장면 ③ 감정 판정 ④ 확산 신호 중 **둘 이상**. 순서는 전환 서사(가장 큰 집단) → 장면 → 확산 신호. 불만 후기는 05에 두지 않고 09 조건·11 Q&A로.
- **가공**: 해요체 통일(반말·ㅋㅋ·이모티콘 미반영, 구어 어미·줄임말 허용) / 카드마다 원문의 구체 디테일 1개 이상 / 사소한 아쉬움·전제 한 줄 허용 / 문장 수·길이·순서를 일부러 다르게 / 같은 동사·결구 반복 금지 / 카피라이터식 정리 문장 금지. 점검: 이어 읽고 "한 사람이 썼나?"에 '아니오'.
- **자사 후기가 없을 때**: 동일 제품 공개 후기 2~4건을 섞어 재구성할 수 있다(대가 지급·사용 전·홍보 복사 리뷰 제외, 브랜드·판매처·수치 제거, 평가 방향·조건은 원문 집단 유지). 묶음 위 고지 1줄(`같은 제품 사용자들의 공개 후기를 바탕으로 재구성한 내용입니다.`)은 유지하고, 합성 원천은 기획안 부록에 남긴다.
- **헤더**: 출처·판매처·'같은 제품'을 말하지 않는다(고지가 맡는다). 수치 없는 짧은 명사형 10자 안팎, 물렁한 말(이야기)보다 단정형.
- 별점·아바타·가명·평균·"N명"은 쓰지 않는다. 표준 템플릿에 별점이 고정돼 있으면 광고주 판단 항목으로 올린다.

### 4-5 설계(06): 설계도와 함께 건네는 자신감
- KEY는 구조 사진 앞에 **"이렇게 만든 데는 이유가 있다"는 자신감**을 서술문 한 줄로. 구조 전체를 가리키고, 아래 부품 소제 전부가 KEY를 받아야 한다.
- KEY에 넣지 않는 것: 부품·동작 하나(그 부품의 SP가 된다), 목차 안내문(`세 부위가 하는 일`), 의인화·업무 어휘, 배제 대상·소재 명사, 이점어, 제품 요약.
- 스왑 테스트 면제(06은 차별화가 아니라 이해·신뢰). 점검: 소제를 하나씩 가리키며 "KEY가 이것도 받는가" / 07로 옮기면 어색한가(어색해야 정상).
- 부품 소제는 `부품명 — 하는 일(동작 명사형)`. 이점어는 설명 줄이나 07로.

### 4-6 셀링포인트(07): 차이 하나
- SP 한 칸 = 행동표 집단 하나와의 **차이 하나**. 두 이점을 한 KEY에 묶지 않는다.
- 스왑 테스트는 "경쟁품에도 있다"로 끝내지 않고 **같은 정도·범위·조건으로 되는가**를 묻는다. 범위 차이는 숫자 없이 결과 어휘(원하는·그대로·넉넉한)로.
- 06 소제로 쓴 부품명을 07 KEY에 다시 쓰지 않는다(훅은 동작·효과로).
- **KEY + 이미지가 기본**, 설명은 없어도 된다. 쓸 때는 KEY에 없는 새 정보 한 줄까지. 구조는 06, 조건은 09, 안전은 11로 보낸다.

### 4-7 비교(08): 한 화면 ○△✕
- 한 화면(모바일 1스크린)에 전부. 열 ≤3(우리 + 대체 유형 2), 행 3~4, 열 머리 = 썸네일 + **통용 유형명**(같은 어미). 표 아래 글 없음.
- 셀은 ○△✕만. **이분 사실**(있다/없다)에만 쓰고 연속량(세기·속도·범위)은 넣지 않는다. △는 "조건이 붙어 된다"일 때만. 검수: "이 판정이 어떤 제품을 가져와도 같은가."
- 기준 행은 명사형 2~6자, **○ = 좋다**로 극성 통일, 다수 집단 불편 빈도순, 비교 축 하나. 우리 열이 전부 ○여도 되지만 사실과 다른 ○·무의미 행은 금지. 조건·한계는 09·11에서 보존.
- 표준 템플릿이 2열 카드라면 **같은 기준(설치 / 거치 / 이동)으로 2열 3항목**에 압축한다.

### 4-8 제품정보(09)·고시(10)
- 스크린별 명사 헤더. 설치면·호환·관리 같은 **조건은 여기서 보존**한다(07에서 뺀 조건이 모이는 곳). 정보 행은 명사형 개조식으로 어미를 맞춘다.
- 보류 항목(치수·소재·구성·보증)은 `(보류: 항목)`으로 표시하고 확정 후 치환. "확인 중" 류를 소비자 화면에 싣지 않는다.

### 4-9 Q&A·주의사항(11)
- **구매 전에**(사기 전에 묻는 것: 내 환경 → 내 기기 → 계절 → 해제·이동 → 없는 기능) / **사용 중에**(부정 리뷰 빈도순 3~6). 전 문항 펼침. 증상 질문을 구매 전 단에 두지 않는다. 희귀 질문(1~2건)은 넣지 않는다.
- 질문은 소비자가 문의창에 쓰는 말로. 답은 결론 → 조건 → 조치, 합쇼체 90자 안팎. 보류 답변이 달릴 문항은 뺀다.
- 주의사항은 법령·안전 최소선만(법령 문구 1회 포함). 책임 배제 문장 금지. Q&A와 중복 항목은 뺀다.

### 4-10 고정 영역: 정품 인증(01)·브랜드(12)·내부 제작(13)
- 01은 승인 공용 원본, 판매 주체, 실제 지원 조건만. 성능·안전 인증이나 브랜드 역사로 확대하지 않는다. 보증·교환 약속은 **승인 전에는 소비자 원고 보류**(오퍼 설계는 사업 결정이며 상세의 독립 영역이 아니다 — 결과만 01·09·08에 녹인다).
- 12는 승인 공용 원고·로고·실제 지원 약속만. 01과 기능 나열을 반복하지 않는다. 표준 템플릿의 영문 슬로건·저작권 고지는 그대로 둔다.
- 13(내부 제작)은 소비자 본문이 아니다. 기준 이미지, 촬영·연출·시험 구분, 오해 방지, 모바일 검수를 기록하는 자리.

## 5. 모바일 스크린 설계 (권장치, 검수는 390px 실기기)

- **스크린 단위**: 780×1300px(390px 화면 한 번에 보이는 분량). 한 스크린 한 생각: 이미지 1장 + KEY 1~2줄 + 보조 1줄. 본문 3문장 이상이면 스크린을 나눈다.
- **한 스크린 한 이미지** (최소선): 2·3·4분할, 콜라주, 나란히 둔 비교 컷을 쓰지 않는다. 순서·동작은 GIF 한 장(마지막 프레임 = 결과), 비교·전후는 정답 한 장 + 텍스트, 여러 자리·경우는 도해 한 장에 마커. 예외는 표 안 썸네일과 한 장면 플랫레이.
- **가로 3칸 금지**: 390px에서 칸당 120px가 되어 읽히지 않는다. 2열까지(비교 컷 예외), 접사는 한 컷 한 부품.
- **글자 크기**(780 기준): 제목 56~60px(KV 64 허용), 보조 30, 캡션 26, 정보 영역 헤더는 한 단계 작게. 질문 30 굵게 / 답 26.
- **텍스트 총량**: 영역당 상한을 정해 둔다(예: KV 60자 / 타겟 160 / 위험 220 / 설계 260 / SP 각 120 / 비교 300 / 정보 스크린당 120 / 답변당 90). 넘으면 스크린을 나누거나 줄인다.
- **긴 정보**: Q&A처럼 글이 긴 영역은 1300px를 넘기 전에 스크린을 나눈다(사용 중 3문항 + 주의 7항을 한 스크린에 두면 넘친다).
- 점검: 한 스크린을 2초 안에 읽을 수 있는가 / 이미지가 몇 장인가(2 이상이면 바꾼다) / 영역 지도·요약표가 확정 카피와 같은가.
- **기획안 기록 항목**(대시보드 6필드): 메시지·목적(`message`) / 소비자 카피(`copy`, 화면에 나갈 글만) / 화면 구성(`visual`) / 근거(`evidence`, 쓸 수 있는 표현 범위까지) / 제작 요청(`productionBrief`, 재사용·새 촬영·시험·조판) / 확인 항목(`missingFacts`). 못 쓰는 원고는 빈칸 + 근거·확인 항목으로 남기고, 실험·촬영 요청은 미디어 표시 + 게시 조건으로 적는다. 미디어 요청 표시는 검증 완료가 아니다.
- 규격: 쿠팡 780px(대시보드 기준), 스마트스토어 860px(관행). 390·360px 실기기에서 글자 크기·대비·제품 비율·출처 판독을 본다. 치수 도해는 제품정보에 둔다(사용자 다수가 이미지로 크기를 가늠한다).

## 6. 이미지 — 생성과 요청

### 6-1 피사체 점유율: 글이 줄면 제품이 커진다 (권장)
| 텍스트 층 | 피사체 긴 변의 프레임 점유 |
|---|---|
| KEY 1~2줄만 | 70~80% |
| KEY + 서브·설명 1~2줄 | 60~70% |
| 설명 3줄 이상·표 | 50~60% (표는 표가 피사체) |
- 여백은 텍스트 자리와 피사체 둘레 두 곳만 의도한다. 접사는 프레임을 넘쳐도 되고, 장면 컷은 '제품+손+대상물' 묶음이 피사체. 요청서에 **텍스트 층과 점유율을 함께** 적고, 카피를 줄이면 점유율을 같이 올린다.

### 6-2 텍스트 자리 비우기 (최소선)
- 텍스트가 사진 위에 올라가는 슬롯(KV·히어로·패널 캡션)은 **텍스트가 차지할 영역을 사진에서 비워 둔다**. 본체(특히 어두운 제품)가 텍스트 영역에 올라가면 글이 묻힌다. 생성 프롬프트에 "제품은 프레임 하단 N% 안, 상단은 빈 배경"처럼 **비율로 지시**하고, 결과물에서 제품 상단선이 텍스트 하단선 아래인지 확인한다.
- 하단에 아이콘 띠·캡션 띠가 있는 슬롯은 제품 하단도 띠 위에 두거나, 띠에 가려도 되는 부분(그림자·받침)만 걸리게 한다.

### 6-3 AI 생성 시 형태 고정 (권장)
- 실물 레퍼런스는 **한 장짜리 시트보다 시점별로 잘라 여러 장**(측면·3/4·정면·후면·폴딩·상면)을 넣고, 컷마다 3개 시점 안팎을 함께 준다.
- 프롬프트에 **구조 명세**를 고정한다: 부품별로 형태·색·재질·개수·연결(예: "암은 단일 봉, 힌지 2개, 중간 관절 없음"). 틀리기 쉬운 것은 부정형으로도 적는다("twin rods 아님, telescoping 아님").
- 결과는 레퍼런스와 **부품 단위로 대조**(개수·비율·색·각인)하고, 어긋난 컷만 명세를 보강해 재생성한다. 1차 원본은 버리지 않고 보관한다.
- **톤앤매너 통일**: 한 페이지 안에서 사진과 선화(일러스트)를 섞지 않는다. 위험소구처럼 연출이 어려운 장면도 정차 상태의 사진으로 만든다. 환경·인물은 판매 시장(한국)과 이질적이지 않게(실내·거리·손).
- 제품 사진류는 전부 **시안**이다. 게시 전 실사 교체 대상과 게시 가능(도해·텍스트 영역)을 README에 구분해 둔다.

### 6-4 비율은 슬롯 실측으로
- 조판 레이아웃이나 표준 템플릿이 정해져 있으면 **슬롯의 실제 렌더 크기(px)를 측정**해 그 비율로 생성한다(9:16 · 16:9 · 21:9 · 1:1 · 4:5 등). 정사각 원본을 가로로 자르면 피사체가 잘린다.
- 측정값은 요청서에 함께 적는다(예: "히어로 840×500 cover, 캡션 중앙 → 중앙을 어둡고 비워서").

### 6-5 법·플랫폼 최소선 (대시보드 B6·A3)
- 사실 주장은 판매자가 실증한다(표시광고법). 최고·1위·유일은 근거·조사 범위·시점 없이는 쓰지 않는다. 문장 하나하나가 참이어도 **전체 인상**이 오인을 주면 안 된다 → 위험 → 설계 → SP → 비교를 **연속해서 읽어** 안전 보장 암시가 없는지 본다.
- 상품명 금지 문구(최저가·특가·무료배송 등), 체험단 후기의 대가 표시, 상품정보제공고시·KC 해당 여부 확인. 카테고리별 안전 법령(차량이면 도로교통법 §49·에어백 부위 설치 금지)은 Q&A 주의사항에 한 번.
- 금지: 근거 없는 확률·반응시간·세기·고정 보장, 가격 상승·품절 공포, 사고·충돌 연출, 타사 카피·수치·인증·후기 이식, 가짜 후기·가짜 인증, 책임 배제 문장("불량이 아닙니다").
- 광고·숏폼 소재는 상세 밖이지만 같은 안전 규칙을 준용한다(실주행 영상은 고정 카메라·운전자 무조작, 0~3초 시연 훅, 본문 고정 + 훅 3~5개 변형).

## 7. 표준 템플릿(조립 스튜디오 '원본') 적용

> 기획안 원안을 대시보드 조립 스튜디오의 문제해결형 표준 템플릿에 넣을 때의 원칙. **원안이 기준이고 템플릿 적용본은 그 적용**이다. 둘의 차이는 기획안 §S 대조표에 남긴다.

### 7-1 기본 흐름을 지킨다 (최소선)
- 템플릿의 **영역 구성·순서·개수를 그대로** 쓴다. 영역을 추가하거나 빼지 않는다(추가 SP 기능이 있어도 쓰지 않는 것이 기본). 템플릿에만 있는 영역(라이프스타일 등)은 비우지 말고 원안의 가까운 내용으로 채운다.
- 슬롯이 없는 원안 카피는 **가장 가까운 영역으로 옮기거나 뺀다**(예: KV 조건 라벨 → 제품정보·Q&A, 별도 SP → 메인 아이콘·설계 설명·비교표). 옮긴 내용은 대조표에 적는다.
- 템플릿 구조상 필요한 요소(예: 위험소구의 수치 3칸)는 **출처가 분명한 사실**로만 채우고, 가이드 예외임을 표기해 사람 검토로 올린다.

### 7-2 글자 수는 슬롯 원문이 상한 (권장)
- 템플릿 원문의 **슬롯별 글자 수·글자 크기·너비를 실측**해 표로 두고, 그 글자 수를 상한으로 카피를 줄인다. 키 카피의 느낌은 유지하되 길이만 맞춘다(예: 후기 본문 카드당 65~75자, 카드 제목 3~6자, 부품 설명 16~18자).
- 줄바꿈이 들어가는 헤드라인은 **두 줄로 나뉘는 자리까지** 맞춘다. 세 줄로 꺾이거나 한 글자가 홀로 남으면 줄인다.
- 템플릿 고유 문구(영문 슬로건, 저작권 고지, 아이브로 번호)는 그대로 둔다.

### 7-3 고정 블록 처리
- 템플릿에 고정된 부속 블록(두 번째 헤드라인 + 사진, 카드 구석의 작은 이미지)은 **빈칸으로 두지 않는다.** 두 가지 중 하나: ① 원안의 다른 KEY를 넣어 의미 있게 쓴다 ② 광고주가 빼라고 하면 **영역 완성 이미지(sectionImage)**로 그 블록 위까지만 잘라 넣거나, 투명 이미지로 비운다. 비운 뒤 빈 배경 띠가 남는지 렌더로 확인한다.

### 7-4 이미지는 슬롯 비율로 (최소선)
- 6-4의 실측 비율로 생성하고, 텍스트와 겹치는 슬롯은 6-2를 적용한다. 작은 인셋 슬롯(≈0.8)·초광각 슬롯(21:9)은 별도로 만든다.
- 템플릿의 사진 스타일(무지 배경 스튜디오 컷인지, 실내 장면인지)을 따른다. SP가 무지 배경이면 우리 SP도 무지 배경으로.

### 7-5 검증과 저장
- 스튜디오의 검증 함수(`validate`·`verifyImages`)를 통과시키고 1000px로 전체 렌더해 **겹침·넘침·빈 블록을 눈으로** 확인한다.
- 서버 저장 뒤 revision을 기록한다. 수정은 새 안을 만들지 말고 **같은 디자인안의 revision을 올린다.**
- 산출물 세 가지: 디자인안 JSON(가져오기용) · 렌더 미리보기 · 기획안 §S 대조표(원안 ↔ 적용본, 뺀 것·옮긴 것·예외).

## 8. 검수

### 8-1 작성·검수 분리 (권장)
- 작성 에이전트(후보 생성)와 검수 에이전트(채점·채택)를 나눈다. 검수는 **스캔 → 상위 3안 → 채점**으로 짧게, 영역을 2~3묶음으로 나눠 병렬.
- 채점 항목: 즉시 이해 / 다수 집단과의 차이 / 레퍼런스 형식 / 사실·보편성 / 자연스러움 / 글자 수 / 어필. **표현 수위(과장·오인)는 채점하지 않고 사람 검토 표로** 올린다.
- 브리프에는 행동표(1-1)·보편성 테스트(1-2)·용어표(2-1)를 반드시 첨부한다.

- **역할 분리**: Writer(단위당 키 5안·보조 3안 이내, 의도·리스크 메모, 추천 1순위) / Reviewer(채점·채택·차순위·사람 검토 표, 가이드 12문항·법 점검) / Orchestrator(브리프, 대조, 기획안 반영, 바꾼 이유 기록). Reviewer는 채점을 끝낸 뒤에만 Writer의 추천 표시를 본다(앵커링 방지). 전 후보 탈락 단위는 탈락 이유를 붙여 재작성 요청(최대 2회). 두 에이전트 모두 이전 버전 문서를 열지 않는다.
- **채점**: 각 0~2점 × 6~7항목, 합계 10점 이상 채택, 동점이면 어필 → 차이 순. 하드 탈락은 주행 중 조작 권장·느낌표·법령 위반뿐. 채택안 수정은 **단어 2개 이내**(최소 수정 원칙), 더 큰 수정은 라운드를 다시 돈다.
- **한계를 적어 둔다**: 같은 모델이면 어휘 취향이 겹친다(브리프에 다양화 지시). 채점은 형식 일치도이지 전환율 예측이 아니다.

### 8-2 자체 점검 루프
- 광고주 피드백 한 건마다 **원인 표 → 지침 제안(컨펌 대기) → 잠정 적용 → 컨펌 후 보편화**의 순서로 기록한다. 지침은 다른 상품에도 적용 가능하게, 길이·개수는 권장치로 쓴다.
- 컨펌된 카피는 최소 수정 원칙(2-1)으로 보호한다.

### 8-3 게시 전 전수 점검 체크리스트
- [ ] 어투: 같은 영역 안 어미 통일, 지칭어 통일, 치환 잔재(오타) 없음
- [ ] 레이아웃: 스크린당 이미지 1장, 가로 3칸 없음, 1300px 초과 없음, 글자 크기·텍스트 총량
- [ ] 이미지: 레퍼런스와 부품 대조, 텍스트 영역 비움, 톤앤매너(사진/선화 혼용 없음), 한국 환경
- [ ] 사실: 보류 항목 치환 여부, 법령 문구 1회, 책임 배제 문장 없음, 수치 출처
- [ ] 템플릿: 영역 순서·개수 원본과 동일, 슬롯 글자 수 이내, 고정 블록 빈칸 없음, 검증 통과, revision 기록
- [ ] 문서: 기획안 정리판(확정만) + 탐색 기록판 분리, §S 대조표, README의 시안/실사 구분

### 8-4 최종 검수 12문항 (대시보드 A6, 통과 조건 — 생략 불가)
1. 01~12 순서를 유지했고 13을 소비자 본문에 덧붙이지 않았는가 2. 키비주얼을 전체 설득의 압축판으로 만들지 않았는가 3. 제목·본문·이미지가 영역 역할에 맞고 같은 공식으로 만들지 않았는가 4. 03 자기 해당성 / 04 실제 위험 / 05 실제 경험 / 06 설계·검증 / 07 개별 이점 / 08 자사 선택 이유를 각각 맡는가 5. 소싱명·일반명을 키카피로 쓰지 않았는가 6. 위험 상황 → 발생 경로 → 피해 → 준비 필요성이 이어지는가 7. 일반 위험 근거를 제품 효능으로 바꾸지 않았고, 연속으로 읽어도 안전 보장 암시·주행 중 조작 권장이 없는가 8. 기능명·명사형·정보표를 억지로 이점 문장으로 바꾸지 않았는가 9. 후기·시험·수치·인증·비교에 실제 자료가 있는가 10. 비교가 조건과 한계를 보존하는가 11. FAQ가 실제 질문에 답하고 고시·주의사항이 읽히는가 12. 모바일 실제 결과물로 확인했는가
