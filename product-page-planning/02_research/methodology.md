# 한국 이커머스 상품 상세페이지 기획 방법론: 리서치 노트

> 조사일: 2026-11-09 · 방법: WebSearch 결과 요약만 사용했고 원문은 열람하지 못함(WebFetch 차단 환경).
> 표기 규칙
> - **[공식]**: 플랫폼·정부·법령·연구기관 1차 자료에서 확인
> - **[실무]**: 국내 외주사·마케팅 블로그·교육업체의 공통 주장(검증 수준 낮음)
> - **[업체 주장]**: 근거 공개 없이 자사 데이터나 경험으로 제시한 수치
> - **[미확인]**: 검색으로 확인하지 못함. 공식 문서를 직접 대조해야 함
>

## 0. 핵심 결론 요약

1. 기획은 **리서치(경쟁사·불만 리뷰) → 고객 정의 → USP(1~3개) → 구성 → 카피 → 디자인 → 검수(법·플랫폼·모바일)** 순서로 진행하는 것이 국내 실무 자료의 공통 흐름이다. 단일 표준은 없다 [S1][S2][S20][S21].
2. 대표 구성은 **후킹(결론 먼저) → 공감(문제) → 해결 → 증거 → 신뢰·리스크 제거 → 혜택 → CTA**이다. 고관여 제품은 신뢰·FAQ 블록을 두껍게 하고, 저관여 제품은 짧게 CTA로 보낸다 [S1][S22].
3. "구매 결정은 스크롤 3번 이내"라는 주장은 와디즈 공식 블로그에서 나왔다(750만 서포터 데이터 기반, **[업체 주장]**) [S5]. NN/g 아이트래킹에서는 첫 화면이 열람 시간의 약 57%, 두 화면까지가 약 74%를 차지한다는 수치가 2차 자료로 반복 인용된다 [S14].
4. 이미지 가로폭은 **쿠팡 780px, 스마트스토어 860px**이 사실상 표준이지만, 플랫폼 공식 문서에서는 확인하지 못했다 [S6][S7][S8].
5. 법적으로는 **최상급·배타적 표현(최고·최초·유일·1위)은 실증 책임이 판매자에게 있고**(표시광고법 제5조), 근거가 없으면 삭제하거나 완화해야 한다 [S23][S24][S25].
6. 쿠팡은 **2025-09-19부터 호환용 상품 가이드라인**을 시행했다. 상품명에 '호환'을 넣고, 정품 브랜드명을 상품명 맨 앞에 둘 수 없으며, 상세설명에 "본 제품은 제3자 호환 상품으로 정품이 아닙니다." 문구를 넣어야 한다(2차 자료 기준) [S28][S29][S30].

## (A) 기획 프로세스 단계별 체크리스트

### 1단계: 리서치
- [ ] 경쟁 상위 5~10개 상품의 상세페이지 구성 블록을 순서대로 캡처하고 표로 정리 [S21]
- [ ] 경쟁사 **불만 리뷰(1~3점)** 수집. 불만은 결제 직전에 이탈하게 만드는 지점이므로 "상세페이지에서 먼저 지울 불안 목록"으로 쓴다 [S20]
- [ ] 긍정 리뷰에서 **고객이 실제로 쓰는 말**(사용 상황, 시점, 결과)을 수집. 카피 재료로 쓴다 [S20]
- [ ] 카테고리 관여도 판단. 가격이 아니라 **구매 전 고민 시간**으로 판단한다 [S22]
- [ ] 해당 품목의 상품정보제공고시 품목군과 KC·전파 인증 대상 여부 확인 [S31][S32]

### 2단계: 고객 정의
- [ ] 페르소나 1~2개를 정한다. 리뷰 문장에서 상황, 문제, 사용 타이밍을 뽑는다 [S20]
- [ ] 구매 전 질문(호환, 사이즈, 배송, 반품, 내구성)을 목록으로 만든다. 이 목록이 FAQ와 신뢰 블록의 재료가 된다 [S1][S19]

### 3단계: USP
- [ ] 소구점 후보를 모두 적은 뒤 **메인 1개 + 보조 2개 이내(최대 6개 이하)**로 압축 [S2][S3]
- [ ] 제품 특징(스펙)을 고객 경험(결과)으로 바꿔 쓴다. 예: "고농축" → "적게 써도 오래 간다" [S20]
- [ ] 모든 USP마다 **증거 자료**(시험성적서, 인증, 수치, 전후 비교)를 짝지어 둔다. 증거가 없는 USP는 표현을 완화한다 [S23]

### 4단계: 구성(와이어프레임)
- [ ] 유형을 선택한다(문제해결형, 디자인강조형, 스펙·호환확인형). (B) 참조
- [ ] **첫 화면(스크롤 없이 보이는 영역)**: 대표 이미지 1장과 "무엇이고 왜 필요한가"를 담은 한 줄 [S9]
- [ ] **상단 3섹션**: 문제 공감 → 해결책 → 신뢰 지표(판매량, 리뷰 수, 인증) [S9]
- [ ] 리스크 제거 블록(배송, 교환, 환불)은 CTA 근처에 둔다 [S1][S19]

### 5단계: 카피
- [ ] 메인 카피와 인트로 소구점을 일치시킨다 [S2]
- [ ] 형용사("좋아요", "효과적")를 **수치와 근거**로 바꾼다. 와디즈에서도 같은 조언을 한다 [S4][S12]
- [ ] 최상급·절대 표현을 점검한다. (D) 금지·주의 목록과 대조한다
- [ ] 도입부 카피는 와디즈가 제시한 3가지 유형(감성형, 충격·데이터형, 한 줄 메시지형) 가운데 하나로 쓴다 [S5][S11]

### 6단계: 디자인
- [ ] 가로폭은 플랫폼 기준으로 맞춘다(쿠팡 780px, 스마트스토어 860px). (C) 참조
- [ ] 모바일 1열 구성을 기본으로 한다. 3열 레이아웃은 모바일에서 무너진다 [S10]
- [ ] 크기 비교 컷(In-Scale), 사용 장면, 리뷰어 사진 스타일 컷을 넣는다 [S15][S16]
- [ ] CTA, 혜택 배너는 본문과 다른 색으로 둔다 [S1]

### 7단계: 검수
- [ ] 실제 휴대폰에서 글자 크기와 대비를 확인한다. 15px 이하 글자와 저대비 회색 캡션은 모바일 가독성 문제로 지적됐다 [S9][S10]
- [ ] 최상급 표현마다 비교 범위, 조사 기관, 조사 시점, 기준이 화면에 함께 표기됐는지 확인 [S24]
- [ ] 타사 상표·로고 사용 여부, '호환' 표기, 정품 아님 안내 문구 확인 [S28][S29]
- [ ] 상품정보제공고시 항목과 KC 인증번호 기재 [S31][S32]
- [ ] 와디즈는 오픈 전 AI 심사(최대 5회)로 오해 소지 표현을 사전 점검 [S27]
- [ ] 출시 후에는 A/B 테스트로 검증한다. 업계 전환율 수치는 대부분 근거가 약하다 [S1][S19]

## (B) 섹션 구성 템플릿

**언제 쓰나**: 고객이 불편을 이미 인식하고 있고, 제품이 그 불편을 해결하는 경우. 국내 실무 자료에서 가장 많이 권하는 구성이다 [S1][S17].

| 2 | 공감 | "혹시 이런 상황 불편하지 않으셨나요?" 식의 문제 장면 | [S17] |

### 템플릿 2: 디자인·감성 강조형(패션·인테리어·선물·디자인 액세서리)
**언제 쓰나**: 기능 차이는 작고 외형이나 무드가 구매를 결정하는 경우. 스펙을 위에서부터 길게 나열하면 고객이 "비교 모드"로 들어가 구매가 늦어진다는 지적이 있다 [S18].

| 2 | 사용 장면 갤러리 | 생활 속 연출 2~4컷(장면과 결과를 먼저 보여준다) [S18] |

### 템플릿 3: 스펙·호환 확인형(전자기기 액세서리, 부품, 소모품)
**언제 쓰나**: "내 기기에 맞나?"가 구매의 첫 관문인 경우. 예: 휴대폰 케이스, 충전기, MagSafe 호환 액세서리. Baymard 모바일 연구에서는 호환 의존 상품을 찾는 것이 특히 어려웠고, **상품페이지에 호환 목록을 찾기 쉽고 훑기 쉬운 형태로 제공**하라고 권한다 [S36][S37].

| # | 섹션 | 내용 |
|---|------|------|

| 2 | 호환 기종표 | 지원 모델과 미지원 모델을 명시한 표. 기술 용어라도 구체적으로 쓴다 [S38] |

| 4 | 사용 장면 / USP | 자력, 충전 속도 등. 수치는 시험 조건과 함께 표기 |
| 5 | 비교표 | 자사 모델 간, 또는 기준 규격과 비교. 타사 실명 비교광고는 법적 위험이 있다 [S24] |

| 9 | 고시 정보·CTA | |

### 와디즈 스토리 구성(참고)
- 와디즈 공식 브런치: 프로젝트 생성 → 목표 금액 → 리워드 설계 → **스토리(계기, 매력 포인트, 제작 계획)** → 오픈 [S4]
- 와디즈 메이커센터 영문 가이드 요약: **Grab Attention → Highlight Benefits → Build Trust → Emphasize Why to Back**의 4단계. 고매출 스토리의 66%가 도입부에 구체적 숫자를 사용했다고 한다 [S11]. 105개 프로젝트를 분석했다는 출처가 다른 검색에서는 재확인되지 않아 **[미확인]**으로 둔다.
- 신뢰가 펀딩 성공에 가장 큰 영향을 준다. 메이커 소개와 실물 사진을 넣고, 로고·제품 사진·AI 이미지로 메이커 사진을 대체할 수 없다. 인증이나 객관 데이터는 상단에 배치하고, 없으면 전후 사진이나 테스트 과정을 보여준다 [S12][S13]
- 민간 블로그가 제안하는 스토리 흐름: 브랜드 소개 → 문제 인식·해결 결심 → 제작 여정·장벽 → 전환점 → 가치 → 응원 메시지 [S13]

### 유형 선택 기준(종합, 실무 판단)
| 기준 | 문제해결형 | 디자인강조형 | 스펙·호환형 |
|------|-----------|-------------|-------------|
| 구매 결정 요인 | 불편 해소 | 외형, 무드 | 적합성, 성능 |
| 첫 화면 | 결론(효과) | 무드 컷 | 호환 기종, 핵심 스펙 |
| 증거 형태 | 전후 비교, 테스트 | 고객 사진, 착용 컷 | 시험 수치, 인증, 호환표 |
| 리스크 블록 | 환불 보장 | 교환, 사이즈 | 호환 불가 시 반품 |
| 관여도 | 중~고 | 저~중 | 고(비교 행동이 확실히 일어남) [S22] |

> 유형별 학술적 정의는 검색으로 확인하지 못했다. 위 표는 [S17][S18][S22][S36]을 종합한 실무 판단이다.

### 모바일 우선 원칙
- 모바일 사용자는 정독하지 않고 빠르게 훑는다. 시각 요소로 템포를 조절해 핵심만 남긴다 [S1]
- **첫 화면**에는 대표 이미지 1장과 "무엇이고 왜 필요한지" 한 줄. 이 한 줄이 약하면 스크롤이 이어지지 않는다 [S9]
- **첫 3스크롤 규칙**: 와디즈는 구매 여부가 스크롤 3번 이내에 결정된다고 주장한다(750만 서포터 데이터, **[업체 주장]**) [S5]. 한 셀러 교육 자료는 상단 3섹션을 **문제 공감 → 해결책 → 신뢰 지표**로 짜라고 권한다 [S9]. "첫 3초에 80%가 이탈" 같은 수치는 근거가 없다 **[업체 주장]** [S9]
- NN/g(2018, 2차 인용): 첫 화면이 페이지 열람 시간의 **57%**, 두 화면까지가 **74%**를 차지했다(2010년에는 80%). 모바일에만 해당하는 수치인지는 **[미확인]** [S14]
- **스캐닝 패턴(NN/g)** [S40][S41]
  - F자형 패턴: 첫 줄은 주목받고 이후 단락은 앞의 몇 단어만 읽힌다. 구분 없는 텍스트 덩어리일 때 주로 나타난다
  - 레이어케이크 패턴: 사용자가 제목과 소제목을 주로 보고 본문은 가끔 읽는다. 상세페이지에서는 **섹션마다 결론형 소제목**을 다는 것이 핵심이다
  - 그 밖에 스팟형(특정 정보 탐색), 바이패싱, 커밋먼트 패턴이 있다
  - 대응: 명확한 소제목, 불릿, 굵은 글씨, 관련 정보 묶기
- 글자 크기와 대비: 15px 글자와 저대비 회색 캡션은 모바일 가독성 문제로 진단됐다. 본문 텍스트를 이미지에 넣을 때는 모바일 축소 배율을 고려해 키운다 [S10]
- 레이아웃: 3열은 모바일에서 무너지므로 1열이나 2열로 구성한다 [S10]
- 스마트에디터 ONE에 HTML을 붙여넣으면 일부 CSS가 무시된다(허용 목록 비공개). 이미지 위주로 만들고 텍스트는 보조로 쓰는 것이 안전하다 [S10]
- 쿠팡 상품명은 모바일 가독성을 위해 80자 이하 권장 [S26]

### D-6. 타사 상표('MagSafe' 등) 사용 관행과 리스크

## 유튜브 실무 채널(디선제압, 셀디, 온크트리, 피쳐링스튜디오, 창업신내림) 확인 결과

- 다섯 채널 모두 **검색 결과에서 채널명과 직접 연결된 블로그, 기사, 요약글을 찾지 못했다 [미확인]**. "셀디"는 인프런 셀피쉬클럽 강의가, "창업신내림"은 무관한 결과만 나왔다 [S53][S54]
- 대신 국내 상세페이지 교육·실무 자료 전반에서 반복되는 공통 원칙은 다음과 같다(채널 원칙으로 귀속하지 말 것)
  1. 기획과 디자인을 분리하고, 기획을 먼저 한다 [S21]
  2. 소구점은 메인 1개, 많아도 6개 이하로 줄이고, 인트로 카피와 메인 소구점을 일치시킨다 [S2][S3]
  3. 첫 화면에서 결론을 먼저 말한다(후킹) [S1][S9]
  4. 스펙 나열보다 사용 장면과 결과를 먼저 보여준다 [S18]
  5. 모든 정보를 다 넣지 않는다. 정보가 많을수록 결정 포인트가 흐려진다 [S18]
  6. 경쟁사의 불만 리뷰를 불안 제거 목록으로 쓴다 [S20]
  7. 신뢰 지표와 리스크 제거 블록은 CTA 근처에 둔다 [S1][S9]
  8. 모바일 가독성(폰트, 행간)을 실기기로 검수한다 [S9][S21]
- 후속 조치: 채널 URL이나 대표 영상 제목을 받으면 재검색할 수 있다
